# Ядро agentgraph: правила правок в `src/`

Стек: Node ≥20, TypeScript strict, ESM (`module: NodeNext`), три зависимости — `@anthropic-ai/claude-agent-sdk`, `yaml`, `zod`. Скилл загружается, когда правка касается `src/`; это те же правила, что раньше лежали в сабагенте core-engineer, но работа идёт в основной сессии: она уже видела задачу, обсуждение и соседние файлы, и пересказывать их отдельному агенту не нужно.

## Как устроен код
Карта модулей — таблица «Как устроен код» в `docs/GETTING_STARTED.md`. Прочитай её перед работой и обнови, если добавил модуль или сменил ответственность файла.

## Правила
- Импорты локальных модулей — с расширением `.js` (`./runner.js`), стандартная библиотека — с префиксом `node:`.
- Новых npm-зависимостей не добавляй. HTTP — голый `node:http`, без фреймворков. Если зависимость действительно нужна, остановись и опиши, зачем.
- Схема flow живёт только в `src/schema.ts` (zod). Новое поле получает `.describe(...)` на русском: по этим описаниям генератор пишет flow. Поле опциональное, чтобы старые `flows/*.yaml` продолжали проходить валидацию.
- Внешние эффекты передаются через `deps` с дефолтом (`runSession(req, log, deps = { query })`). Так тест подменяет SDK, git и время. Настоящую сессию Claude в тестах не запускай.
- Новые эндпоинты сервера проходят через `server-guard.ts` (проверка Host, Origin, типа тела). Пути к файлам запуска открывай через существующие хелперы (`openRunFile` и подобные), не через свою склейку путей.
- Права артефактов (`reads`/`writes`, guard на хуке перед вызовом инструмента) — граница безопасности. Ослаблять их нельзя. Если правка касается guard, напомни прогнать `npx tsx scripts/check-sdk-hooks.mts`, но сам его не запускай: он тратит деньги.
- Веб-интерфейс — `web/` (React; правила — скилл `agentgraph-web`). Он берёт типы ответов API через `import type` из `src/` (лучше из `src/api-types.ts`) и не импортирует из `src/` рантайм. Новый или изменённый ответ API — тип в `src/api-types.ts` и `satisfies` там, где сервер его отдаёт; `npm run typecheck` проверяет и `web/`. Раздача сборки UI — `src/web-static.ts`.
- Комментарии и имена тестов пишутся на русском, коротко, в стиле окружающего кода.

## Порядок работы
1. Найди модуль и соседний `*.test.ts`, посмотри, как там подменяют зависимости.
2. Внеси правку и добавь тест на новое поведение: `test('что происходит', ...)` с `node:assert/strict`.
3. Прогони `npm run typecheck && npm test`. Перед тем как сдавать работу, всё должно быть зелёным.
4. Независимое ревью перед коммитом — сабагент `code-reviewer` (только чтение, свежий контекст): он единственный, кому нужен отдельный контекст, чтобы не быть убеждённым собственными объяснениями автора правки.
5. В ответе перечисли изменённые файлы, что проверено и что осталось непроверенным (например, поведение в живом UI).
