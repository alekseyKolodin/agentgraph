# /agentgraph — запуск flow из чата

Хелпер: `node <директория этого скилла>/agentgraph.mjs <команда>` (директория скилла указана при его загрузке; обычно `~/.claude/skills/agentgraph`, это симлинк на `<корень agentgraph>/.claude/skills/agentgraph`; корень хелпер находит сам по реальному пути скрипта или по `AGENTGRAPH_HOME`). Ниже `AG` = эта команда.
Он ходит в API UI-сервера agentgraph (`http://127.0.0.1:4747`) и сам поднимает сервер (`npm run ui` в корне проекта agentgraph), если тот не запущен.
Запуск идёт через сервер, а не через CLI: в CLI вопросы агента читаются из stdin, которого у Bash нет.

Аргументы пользователя: `$ARGUMENTS`

## 1. Разобрать запрос

Из аргументов и разговора нужны три вещи:

- **flow** — имя из `AG flows` или разовый запуск (см. раздел «Разовый запуск»), если задачу нужно решить через flow один раз, а подходящего сохранённого flow нет. Для сохранённого flow `AG flows` (покажет этапы, условие, `asksUser`, `hasDefaultInput`; у flow из нескольких блоков — `blocks`: блоки по порядку, у каждого свой цикл или один проход);
- **задача** (`{{input}}`) — текст от пользователя; если не дана и у flow `hasDefaultInput: true`, можно запустить с задачей по умолчанию, но сначала скажи об этом;
- **директория проекта** (`--cwd`) — где агенты читают и правят файлы.

Если flow не назван или не найден — покажи список (`AG flows`) и спроси через AskUserQuestion.
Если не названа директория — спроси через AskUserQuestion, первым вариантом предложи текущую рабочую директорию сессии. Никогда не подставляй молча корень проекта agentgraph: это сам инструмент, а не целевой проект.
Если задачи нет и нет задачи по умолчанию — спроси текстом.

Перед стартом одной строкой скажи, что запускаешь: flow, директория проекта, лимиты, и какие этапы имеют право писать файлы или запускать Bash. Явный вызов `/agentgraph` с аргументами — уже согласие на запуск, отдельного «точно?» не нужно. Если пользователь не задал лимит, не придумывай свой.

## 2. Запустить

Задачу передавай через файл, чтобы не ломать кавычки и переносы:

```bash
cat > "$SCRATCH/ag-input.md" <<'EOF'
<текст задачи>
EOF
AG start <flow> --cwd <dir> --input-file "$SCRATCH/ag-input.md" [--add-dir DIR]... [--attach FILE]... [--max-iterations N] [--max-budget USD] [--model M]
```

(`$SCRATCH` — scratchpad-директория сессии.) Ответ: `{ id, ui }`. Дай пользователю ссылку `ui`: там видно этапы, лог и можно отвечать на вопросы самому.

Обе опции повторяемые, `~` раскрывается, отсутствующий путь — ошибка ещё до запуска:
- `--attach FILE` — вложение к задаче: пользователь дал скриншот, макет, лог или документ. Файл ляжет в `runs/<id>/attachments/`, путь к нему допишется в промпт этапов. Открыть его смогут только этапы с Read. Типы: `png jpg jpeg gif webp pdf txt md csv json log yaml yml xml`, до 10 МБ на файл, 25 МБ на все, не больше 10 файлов. `.docx` не принимается: сначала сохрани его в PDF или текст;
- `--add-dir DIR` — дополнительная директория на весь запуск, видна всем этапам (как `--add-dir` у Claude Code): например, соседний репозиторий с правилами или общим кодом.

### Разовый запуск

Flow генерируется под задачу и запускается, но в `flows/` не сохраняется: его единственная копия — снимок `runs/<id>/flow.yaml`, в `run.json` стоит `adhoc: true`. Нужен сервер с фичей `adhoc-runs` (хелпер проверяет сам). Порядок строгий:

1. **Черновик.** Задачу — в файл, как выше, затем:
   ```bash
   AG draft --task-file "$SCRATCH/ag-input.md" --cwd <dir> [--out "$SCRATCH/ag-draft.yaml"] [--model M]
   ```
   Ответ: `{ specFile, name, description, phases, condition, blocks, asksUser, costUsd }`. Ничего не запускается и в `flows/` не пишется.
2. **План пользователю.** Покажи этапы с инструментами (`phases`: в квадратных скобках — `tools`), условие остановки и блоки. Выдели этапы с `Edit`, `Write` и `Bash`: инструменты flow **разрешаются без подтверждения**, агенты будут править файлы и запускать команды в `<dir>` сами.
3. **Явное согласие.** Спроси через AskUserQuestion: «Запустить», «Поправить» (поправь YAML из `specFile` по словам пользователя и покажи план заново), «Отмена». Вызов `/agentgraph` с задачей здесь **не** считается согласием: плана пользователь ещё не видел.
4. **Старт** только после «Запустить»:
   ```bash
   AG start --spec-file <specFile> --cwd <dir> --input-file "$SCRATCH/ag-input.md" [--add-dir DIR]... [--attach FILE]... [--max-budget USD] [--model M]
   ```
   Ответ: `{ id, ui, adhoc: true }`, дальше как обычно — раздел 3.

Если пользователь потом попросит сохранить flow: `AG save-flow <id> [--name N] [--folder D]`. Без `--name` имя свободное (`<имя>` или `<имя>-2`), занятое `--name` — отказ, существующий flow не перезаписывается. Ответ: `{ name, folder }`. Сам запуск остаётся разовым.

Продолжение (`AG continue`) у разового запуска идёт по его снимку, а не по одноимённому flow из `flows/`. Одноблочный запуск продолжить нельзя, как и обычный.

## 3. Ждать вопрос или конец

```bash
AG wait <id>
```

Всегда запускай `wait` **в фоне** (`run_in_background: true`): flow идут минутами и часами. Уведомление придёт, когда команда завершится. Пока ждёшь — не поллить, не спать; коротко скажи пользователю, что запуск идёт.

Вывод заканчивается одним из блоков:

### `=== QUESTION ===`

Агент этапа спрашивает пользователя. JSON: `runId`, `questionId`, `phase`, `questions[]` (`question`, `header`, `multiSelect`, `options[{label, description}]`), иногда `preface` — текст агента прямо перед вопросом (markdown: таблица, список, пояснение).

1. Если есть `preface`, сначала покажи его пользователю в чате дословно: без него варианты вроде «№1, 2, 3, 4» непонятны.
2. Задай эти вопросы через AskUserQuestion **как есть**: тот же текст вопроса, те же варианты, `header` (обрежь до 12 символов), `multiSelect`. В тексте вопроса укажи этап, например «[Аудит ТЗ] …». Не переформулируй и не отвечай за пользователя, даже если ответ кажется очевидным.
3. Собери ответы: ключ — **точный** текст `question`, значение — `label` выбранного варианта; при multiSelect — labels через `, `; при «Other» — свой текст пользователя.
4. Отправь:
   ```bash
   AG answer <runId> <questionId> --json '<{"текст вопроса":"ответ"}>'
   ```
   Если ответ длинный или с кавычками — запиши JSON в файл и передай `--file`. Ошибка «Вопрос не найден или уже отвечен» значит, что пользователь уже ответил в UI — это нормально.
5. Снова запусти `AG wait <id>` в фоне.

### `=== END ===`

Запуск завершён. JSON-сводка: `status` (`done` | `max_iterations` | `failed` | `budget_exceeded` | `aborted` | `interrupted` — процесс раннера умер, не дописав отчёт: сервер перезапустили или он упал), итерации, стоимость, этапы с путями к `output`, условия с замечаниями (`feedback`). У flow из нескольких блоков есть `blocks` (статус и итерации каждого блока), а у этапов и условий — поле `block`. У flow с артефактами — `artifacts` (ключ, путь, кто последним менял, `tasks` — пункты чек-листа) и `decisions` (ключ артефакта для ответов на паузу). `continuable` — можно ли продолжить (`AG continue`), при `false` причина в `continueReason`.

Отчитайся коротко:
- статус и что он значит (для `max_iterations` — что условие (команда, судья или маркер) так и не выполнено, и последние замечания (`feedback`); у многоблочного flow — на каком блоке остановился);
- итерации и стоимость (оценка по прайсу API);
- что получилось: прочитай `output` **последнего** этапа последней итерации и перескажи суть; если flow создавал файлы — назови пути;
- при ошибке — `error` и `errors` упавшего этапа;
- ссылку `ui` для подробностей.

Не вываливай выводы этапов целиком — дай суть и пути.

### `=== PAUSED ===`

Запуск на паузе. Текущий этап доработал, следующий не начался.

**Если в сводке есть `pauseReason`** — паузу попросил агент: у flow задан `loop.pause_marker`, и этап закончил им вывод, потому что дальше без решения пользователя нельзя. В `pauseReason.text` его вопросы и причина, в `pauseReason.output` — вывод этапа целиком.
1. Задай вопросы агента пользователю: через AskUserQuestion, если у них есть варианты, иначе текстом. Укажи этап, например «[Ревью] …». Не отвечай за пользователя.
2. Передай ответ:
   - **если в сводке есть `decisions`** (у flow артефакт для ответов) — запиши ответ пользователя как есть в `$SCRATCH/ag-answer.md` (тем же heredoc, что задачу в шаге 2: `EOF` с начала строки) и возобнови с ним: `AG resume <id> --answer-file "$SCRATCH/ag-answer.md"`. Сервер допишет в конец артефакта запись: время, блок, итерация, этап, вопросы этапа цитатой и ответ; ответ ляжет и в отчёт запуска (`pauses[].answer`). Запуск возобновится только после успешной записи: при ошибке он остаётся на паузе — скажи пользователю причину и не теряй ответ. Сам в файлы артефактов и папку запуска не пиши.
   - **если `decisions` нет** — запиши ответы туда, куда просит агент в `pauseReason.text` (обычно файл решений flow), с пометкой «решение пользователя» и датой. Если агент место не назвал — спроси пользователя, куда; у flow с артефактами место может быть артефактом — тогда правка через `AG artifact-write` (ниже). Затем `AG resume <id>`.
3. Снова `AG wait <id>` в фоне. Следующая итерация прочитает ответ.

**Если `pauseReason` нет** — паузу поставили из UI или через `AG pause`. Скажи пользователю, на каком этапе стоит запуск. Сам не возобновляй. Когда пользователь попросит возобновить: `AG resume <id>`, затем снова `AG wait <id>` в фоне. Если возобновили из UI, тоже просто снова запусти `wait`. Пока запуск на паузе, `wait` сразу возвращает PAUSED, так что не перезапускай его в цикле.

### `=== TIMEOUT ===`

Только если передавал `--timeout`. Запуск ещё идёт — просто снова `wait` в фоне.

## Прочее

- `AG continue <id> [--max-budget USD] [--model M]` — продолжить завершённый не `done` запуск текущей версией flow: блоки, прошедшие целиком, не повторяются, их выводы подставляются в промпты; остановившийся блок идёт с первой итерации. Ответ: `{ id, ui, continuedFrom, skipped }`, дальше `AG wait <новый id>` в фоне. Предлагай его в отчёте о `max_iterations` и об «оборвался» вместо нового `start`, который заново пройдёт все блоки. `--max-iterations` не принимается: лимит блока меняют в flow.
- `AG status <id>` — сводка по любому запуску (живому или завершённому), например если пользователь спрашивает «как там».
- `AG pause <id>` — пауза после текущего шага: идущая сессия доработает, следующая не начнётся. `AG resume <id>` — возобновить. Только по просьбе пользователя.
- **Починить и продолжить тот же запуск** (без «остановить → продолжить»), только по просьбе пользователя:
  - `AG note <id> (--text T | --file F) [--all]` — указание идущему запуску (идёт или на паузе): ляжет хвостом «Указание пользователя» в промпт следующего шага (этапа, всех участников группы или судьи); с `--all` — каждого шага до конца запуска. Текст — словами пользователя; длинный или многострочный — через файл в `$SCRATCH`. Ответ: `{ ok, note, scope }`. Где указание применено — в `notes[].applied` сводки запуска.
  - `AG flow-reload <id>` — пользователь поправил `flows/<имя>.yaml` (например, ты сам по его просьбе): запуск на паузе берёт текущую версию и идёт по ней дальше тем же id. Сначала `AG pause <id>` и дождись PAUSED в `wait`. Ответ: `{ ok, version, changed }` — что поменялось; пустой `changed` — в flows/ та же версия. Неподходящая правка (пройденные блоки, имя, задача, объявления артефактов, переход между одним блоком и несколькими) — ошибка со списком причин, запуск остаётся на паузе со старым flow: покажи причины пользователю. Не у разового запуска. Затем `AG resume <id>` и снова `AG wait <id>` в фоне.
- `AG abort <id>` — остановить запуск. Только по просьбе пользователя.
- **Артефакты запуска** (у flow с `artifacts`: именованные файлы запуска, которые этапы читают и пишут между итерациями):
  - `AG artifacts <id>` — список: путь, кто последним менял, пункты чек-листа (`tasks: { open, done }` — открыто и закрыто; есть только у markdown-артефакта с чек-листом), можно ли сейчас править (`editable`) и почему нет или куда попадёт правка (`note`).
  - `AG artifact <id> <key> [--version N] [--out F]` — шапка (в ней `hash` — база для записи, версии, `editable`, `tasks` — пункты чек-листа текущей версии; с `--version N` поля нет) и текст после `=== TEXT ===`; с `--out F` текст ложится в файл.
  - `AG artifact-write <id> <key> --file F [--base HASH] [--resume]` — записать артефакт из файла как правку пользователя. Только по просьбе пользователя. Правишь по прочитанному тексту — передай `--base` с `hash` из `artifact`: если файл изменили после чтения, придёт отказ с тем, кто и когда менял, — перечитай и согласуй с пользователем. `--resume` — «сохранить и возобновить», только на паузе. Пока идёт шаг, который пишет этот артефакт, запись отклоняется: подожди конца шага или поставь паузу. Правка подхватится со следующего шага; если ответ называет `readers`, эти этапы уже получили прежнюю версию. Завершённый (`done`) и непродолжаемый запуск правок не принимают; у остановленного правка попадёт в продолжение (`AG continue`).
- Живой запуск живёт в процессе UI-сервера. Если `wait` пишет, что сервер недоступен, — запуск прерван; скажи об этом и предложи перезапустить.
- Если хелпер сам поднял сервер (`started: true`), упомяни, что он остался работать в фоне (лог в `log`).
- Скилл живёт в проекте (`<корень agentgraph>/.claude/skills/agentgraph/`) рядом с `src/server.ts`: при смене API `/api/runs`, `/api/flows/generate`, `/save-flow`, `/answer`, `/pause`, `/resume`, `/note`, `/flow/reload`, `/artifacts` правь `agentgraph.mjs` здесь же.
- Команды артефактов и `resume --answer-file` требуют сервер с фичей `artifacts`: хелпер проверяет это и на старом сервере просит перезапустить `npm run ui`, а не теряет ответ молча.
- Сохранённые flow этот скилл не создаёт и не правит (кроме `save-flow` у разового запуска) — для этого UI («Новый flow», Конструктор) или `npm run agentgraph -- gen "…"` в корне проекта agentgraph. Flow из проделанной в сессии работы (с учётом найденных подводных камней) делает скилл `/session-to-flow`.
