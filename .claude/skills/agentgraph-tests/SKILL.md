# Тесты agentgraph

Как здесь пишут и чинят тесты. Скилл загружается, когда нужно покрыть новое поведение, написать регрессию на баг или разобрать падающий `npm test`.

## Как здесь пишут тесты
- Раннер — встроенный `node:test` через `tsx --test src/*.test.ts`, проверки — `node:assert/strict`. Других фреймворков не добавляй.
- Тест лежит рядом с модулем: `src/<module>.test.ts`; у чистой логики UI — `web/src/lib/**/<module>.test.ts` (без React и DOM, `npm test` берёт и их). Для узкой темы — `src/<module>.<тема>.test.ts` (так сделаны `runner.parallel.test.ts`, `agent.tokens.test.ts`).
- Имя теста — русская фраза о поведении: `test('маркер в середине текста паузу не ставит', ...)`.
- Внешние эффекты подменяются через параметр `deps` (например, `runSession(req, log, { query: fake })`). Настоящий Agent SDK, сеть, Jira и glab в тестах не вызываются.
- Файлы создаются во временной папке (`fs.mkdtempSync(path.join(os.tmpdir(), ...))`) и удаляются после теста. `~/.agentgraph` и `runs/` проекта не трогай: подставляй пути через переменные окружения или параметры, как в соседних тестах.
- Один тест проверяет одно поведение, включая граничные случаи: пустой ввод, отсутствующий файл, повторный вызов.

## Порядок работы
1. Прочитай модуль и существующие тесты к нему, переиспользуй их хелперы и фикстуры.
2. Напиши тесты. На баг сначала добейся, чтобы тест падал по правильной причине.
3. Прогони точечно (`npx tsx --test src/<file>.test.ts`), затем весь `npm test` и `npm run typecheck`.
4. Если тест вскрыл баг в коде, не чини его молча: опиши входные данные, ожидаемое и фактическое поведение и место в коде.
