## Боль (слова пользователя)

- Журнал на главной бесполезен: «почти никогда не смотрю и ничего с ним не делаю».
- Окно запуска: «везде инпуты, ничего не понятно, очень сложно разобраться даже мне».
- Конструктор: поле «Правка с ИИ» крошечное, хотя через него работают чаще всего; кнопки рядом и непонятно, за что отвечают; ход правки — нечитаемый сырой лог; итог в markdown показан спецсимволами.
- Важно: большой flow (много блоков и этапов) должен выглядеть так же спокойно, как маленький.

Корень: экраны показывают параметры машины, а не шаги человека; история лежит там, где ждут действий.

## Решения

**Вкладки flow:** «Запуск · Правка · История» (сделано в основе ветки: `FlowScreen.tsx` — только оболочка; `RunTab.tsx`, `EditTab.tsx` с сегментом «Схема | YAML», `YamlView.tsx`, `HistoryTab.tsx`). У черновика нет «Истории».

**Запуск** (`Main`, `RunSetup`, `RunBig`):
- крупное поле «Что нужно сделать» + «Приложить файл» + «Запустить» (⌘↵) в одной карточке;
- ниже три строки словами: «Где работать» (пространство или папка — один выбор, внутри: обновить состояние пространства, отдельная копия репозитория/worktree), «Модель и лимиты» (модель, не дороже $, повторов не больше; у многоблочного — «у каждого блока свои, от N до M»), «Что дать агенту» (теги знаний, другие папки). Поля появляются только по «Изменить/Сменить/Добавить»;
- справа «Что произойдёт»: сверху где спросит тебя, когда закончит, что оставит, сколько стоил прошлый раз; ниже — этапы (один блок) или блоки по строке (несколько блоков; больше восьми — первые шесть и те, где спросит, остальное под «Показать все»); «Открыть схему» → «Правка»;
- снизу «Прошлые запуски» (3 последних): дата, задача, статус, цена, где остановился; «Взять задачу» подставляет текст. «Продолжить с блока N» — только если такое продолжение уже есть в приложении.

**Правка** (`Edit`, `EditWorking`, `EditNode`, `EditBig`):
- слева схема, справа панель «Помощник» (чат): сообщение человека пузырём, ответ ИИ — отрисованный текст (не сырой markdown), список «Что изменилось» строками «новый/правка + этап + одна фраза», клик ведёт к этапу на схеме; предупреждения ИИ — отдельной плашкой; внизу большое поле «Что поменять» (⌘↵ «Отправить»), модель — тихий выбор в шапке панели;
- пока ИИ работает: шаги человеческими словами («Добавил этап…», «Правлю этап…»), таймер, «Прервать»; сырой лог — под «Технический лог»;
- «Сохранить» и «Отменить правку» — в одной плашке «Правка ИИ ещё не сохранена» над схемой (появляется, только когда есть что сохранять; ручные правки — та же плашка без «Отменить правку ИИ»);
- клик по этапу открывает его поля в той же правой панели (сегмент «Помощник | Этап N»), «Все поля списком» убрать; «Добавить этап» и «Настройки flow» — тихие кнопки под схемой;
- большой flow: сверху блоки плитками (название, этапов, повторов, «спросит тебя», «N изменены»), переносятся строками; ниже раскрыт только выбранный блок с этапами и условием повтора; поиск «Найти этап», «Только изменённое», «Развернуть всё». Один блок — сразу развёрнут, как сейчас.

**Главная и история** (`Home`, `History`):
- журнал с главной убрать, доска на всю ширину, в шапке «Все запуски»;
- итог запуска, который требует действия, приходит делом на доску: «упал» (с этапом и действиями), «готов, итог не открыт» (закрывается, когда человек открыл запуск); прерванный человеком — дела нет;
- «История» flow: версии сверху вниз, под каждой — её запуски (дата, задача, статус, цена, где упал); у версии «Что изменилось» и «Вернуть».

## Общие правила для всех сессий

- Только UX, без SEC/PERF-рефакторинга. Границы безопасности сервера не ослаблять.
- Свои файлы — только из своей зоны (в брифе). Общие `store.ts`, `Flow.module.css`, `api` — только дописывать, не переписывать чужое.
- Перед коммитом: `npm run typecheck && npm test && npm run build:web`; e2e (`npm run e2e`) — если менялись экраны, которые он трогает. Проверка в браузере — превью из `.claude/launch.json` (свой порт, не 52364 — там живое приложение пользователя).
- Коммит в свою ветку, в `main` не сливать и не пушить.
