# Сессия правит своё пространство и flow — с вопросом пользователю

Решение владельца: «сессия клода должна иметь возможность с разрешения пользователя менять все что угодно в
пространстве/флоу». Запрет на своё пространство и на flow заменён вопросом на каждую правку — в любом режиме,
`bypassPermissions` и `dontAsk` тоже, у claude 2.1.285+ (прогон `check-sdk-hooks` 2026-11-13 показал, что Claude Code
2.1.285 показывает вопрос хука во всех режимах; claude старше или неизвестной версии в этих двух режимах получает
отказ, как раньше). Остальные границы не тронуты.

> **После этой правки перезапусти на настоящем Claude Code (тратит деньги, сам я его не запускал):**
>
> ```
> npx tsx scripts/check-sdk-hooks.mts --only space-session,session-edit,ask-modes
> ```
>
> Сценарии: `space-session` (сессия в папке пространства), `session-edit` (обычная сессия с пространством + flow, плюс
> шаги `Bash`) и `ask-modes` (claude показывает вопрос хука «ask» в каждом режиме — на этом стоит вопрос agentgraph),
> по режимам `default, acceptEdits, bypassPermissions, dontAsk, auto`. Что прогон показал и какие строки должны стать
> `ok` — раздел «Прогон check-sdk-hooks 2026-11-13».

## Что спрашивается и где

- **Хук `PreToolUse` записи** (`Edit|Write|MultiEdit|NotebookEdit`) — теперь у каждой сессии, с `onFailure: block` на
  claude 2.1.295+. Решение — `editDecision` в `src/session-edit.ts`, путь по realpath и без учёта регистра, относительный —
  от рабочей папки claude в момент вызова. Своё пространство = выбранное сейчас (`rec.space`) + то, в папке которого
  открыта сессия.
- **`permissions.ask`** в `--settings`: папка своего пространства и папка flow — второй рубеж, если хук не ответил.
- **Хук `PostToolUse` записи** (новый): проверенный файл (`space.json`, карта, состояние, flow) — ещё раз на диске, против
  снимка и цели, посчитанных в `PreToolUse` (пространство могли сменить, пока висел вопрос); сломан — откат на снимок
  (новый файл удаляется вместе с опустевшей папкой flow), причина — модели (`decision: block`); событие `space`
  (`spacePart`)/`flows` в `/api/events`.
- **Расхождение симуляции `Edit`** с Claude Code (кавычки-«ёлочки», CRLF) — не отказ, а вопрос с пометкой «проверю после
  записи»; страхует `PostToolUse`.
- **Flow внутри проекта сессии** (сессия в репо agentgraph, где схема может опережать запущенный сервер): ошибка схемы —
  предупреждение в вопросе, без отката после записи.
- **MCP**: `space_map_write`, `space_state_write`, `space_settings`, `flow_write` — в `ASK_TOOLS` (хук `ask` + правило
  `ask`); не прошедший проверку вызов (`askDetail` → `{ deny }`) отклоняется без вопроса.
- **Режимы**: вопрос в каждом — `default`, `acceptEdits`, `auto`, `bypassPermissions`, `dontAsk` (хук `ask`; в
  `acceptEdits` и `auto` его держит ещё и явное правило `ask`); `plan` — claude правки не делает. В `bypassPermissions`
  и `dontAsk` вопрос — только у claude не старше `ASK_IN_ANY_MODE_SINCE` = 2.1.285 (версия — `claude --version` бинарника
  сессии, `rec.claudeVersion`); старше или неизвестной — отказ с причиной в `handleHook`. Проверка содержимого идёт
  раньше вопроса в любом режиме: сломанный `space.json` или flow — отказ и в `bypassPermissions`. Форма agentgraph
  `bypassPermissions`/`dontAsk` не предлагает, но они бывают через `defaultMode` пользователя.

### Где agentgraph вопрос не удержит (и что тогда)

- Хуки выключены у пользователя (`disableAllHooks`, политика `allowManagedHooksOnly`): остаётся `permissions.ask` на своё
  пространство и папку flow (вопрос будет, проверки — нет) и deny на чужие пространства, как раньше. Без хуков у сессии не
  работает и всё остальное (контекст, статус).
- Старый claude (< 2.1.295): сбой хука неблокирующий → решает `permissions.ask` (вопрос, проверки до записи нет; после
  записи `PostToolUse` всё равно перепроверит и откатит).
- Пространство, заведённое после старта сессии: правила его не знают — закрывает только хук (как и раньше у сессии в
  папке пространства). Для сессии **без** пространства вся папка пространств закрыта правилом, как было.
- **`Bash`** (`cp`, `sed -i`, `echo >`) хук записи не видит — как и раньше; Claude Code сверяет файловые команды с
  правилами `Edit`. Прогон 2026-11-13: `cp` в своё пространство в `acceptEdits` — вопрос (правило `ask`; в `default`
  вопрос был бы и без него — `Bash` не разрешён заранее), `>` в чужое — не пишется ни в одном режиме (правило `deny`),
  в `dontAsk` `Bash` не разрешён заранее — отклонён.
  `cp` в своё в `bypassPermissions` тот прогон не проверил: целью была несуществующая `docs/`, и `cp` упал сам. Теперь
  цель — корень пространства, и сценарий меряет это по-настоящему (см. «Прогон check-sdk-hooks 2026-11-13»).
- Папка чтения пространства, которая **содержит** папку flow (например, сам репозиторий agentgraph при
  `AGENTGRAPH_HOME` не задан), остаётся под deny — flow под ней правятся только `flow_write`.

## Как решено с `space.json`

Оба способа: проверка до вопроса в хуке (текст после записи считается как у Claude Code — `Write` целиком, `Edit`/
`MultiEdit` — ровно одно вхождение или `replace_all`, иначе отказ «перечитай») + MCP `space_settings` через тот же
`updateSpace`, что и вкладка «Настройки». Почему не только хук после записи: человек не должен подтверждать файл, который
сломает пространство (его `dirs` станут `--add-dir` всех сессий). Почему не только MCP: бриф требует, чтобы файловые
правки тоже работали. Почему ещё и `PostToolUse`: симуляция `Edit` может разойтись с Claude Code (нормализация кавычек),
поэтому сломанный итог откатывается на снимок. Неизменённые `dirs`/`cwd` не перепроверяются (как у API) — удалённая
рабочая папка не мешает поправить заголовок; сломанный `space.json` сессия может починить.

## Flow, который идёт сейчас

Запуск работает со своим снимком спецификации (раннер пишет `flow.yaml` в папку запуска на старте и идёт по нему);
правка файла flow его не трогает. Оговорка — существующее поведение, не новое: блок-вызов (`flow: <имя>`) грузит
вызываемый flow из `flows/` в момент, когда до него дошёл запуск, так что правка **вызываемого** flow посреди
родительского запуска попадёт в ещё не начатый вызов — так же, как правка из редактора flow.

## Решение после ревью

Независимое ревью (`code-reviewer`) нашло главное: в первой версии у claude 2.1.295+ статический deny на чужие
пространства был снят (его заменял хук — чтобы пространство, выбранное на ходу, правилось файлами без перезапуска). Хук
видит только `Edit`/`Write`/`MultiEdit`/`NotebookEdit`; если Claude Code сверяет файловые команды `Bash` с правилами
`Edit`, это ослабило бы закрытие чужих пространств. Бриф требует их не ослаблять — **deny на чужие пространства
возвращён при любой версии**, а пространство на ходу правится инструментами `space_*` сразу и файлами после
«Перезапустить». Это осознанный компромисс с пунктом брифа «в том числе выбранное на ходу»: файлы `.claude/` и прочие
файлы папки пространства на ходу — только после «Перезапустить» (одна кнопка в `⋯`; она же грузит карту в память).

Исправлено по ревью: подделка `history`/`migratedFrom`/`createdAt` в `space.json` (открыла бы чужие артефакты всем
сессиям пространства) — теперь отказ; повторная проверка после записи сверяет папки со снимком, а не с уже записанным
файлом; цель и снимок хранятся вместе (смена пространства во время вопроса не теряет проверку); ложные отказы симуляции
`Edit` → вопрос с проверкой после записи; `claude.md` в другом регистре — тоже карта; папка настроек = дом/корень/cwd не
считается «служебной»; опустевшая папка flow после отката удаляется; UI не затирает начатую правку, если она появилась,
пока шёл запрос, и не пугает несохранённую карту правкой документа (`spacePart` в событии); текст «идущие запуски
работают со своим снимком» исправлен на точный; тесты на всё это, на папку команд по относительному пути и в другом
регистре, на `AGENTGRAPH_CONFIG_DIR=~`; контрольный сценарий `ask-modes` и шаги `Bash` в `check-sdk-hooks.mts`.

Не исправлено, описано: `Bash` (см. выше); `space_map_write` пишет карту без базы (`mapBase`) — вопрос показывает только
размеры, правка из UI между чтением и вызовом затрётся (у файловой правки это ловит сам Claude Code — «файл изменён
после чтения»); экран открытого flow (`/flow/<имя>`) правку сессии не замечает, и сохранение из редактора без базы её
перезапишет — как и любую внешнюю правку flow сейчас.

## Прогон check-sdk-hooks 2026-11-13 и что поправлено

Пользователь прогнал полный `check-sdk-hooks.mts` на ветке `teamwork` (Agent SDK 0.3.285, haiku 4.5, $1.48).

- **`ask-modes`**: на `ask` хука вопрос (`canUseTool`) был во всех четырёх режимах — `default`, `acceptEdits`,
  `bypassPermissions`, `dontAsk` (`auto` на haiku недоступен). Отказ agentgraph в `bypassPermissions`/`dontAsk` был не
  нужен — **снят**: правка своего пространства и flow, `session_new`, `space_write`, `space_*`, `flow_write` и
  инструменты Teamwork спрашивают в любом режиме. Из `EditScope`/`WriteCall` ушло поле `mode` — решение от режима больше
  не зависит. `ask-modes` теперь не «факт», а проверка: нет вопроса — `FAIL`; плюс контрольная запись без хука
  («без хука (контроль)», `факт`) — видно, что режим переключился и вопрос дал именно хук.
- **Порог версии** (по ревью): измерено на Claude Code 2.1.285 — его везёт Agent SDK 0.3.285, — а сессия запускает
  `claude` из `PATH` (у пользователя сейчас 2.1.318). Поэтому `ASK_IN_ANY_MODE_SINCE = '2.1.285'`, по образцу
  `HOOK_ON_FAILURE_SINCE`: claude старше или неизвестной версии в `bypassPermissions`/`dontAsk` вместо вопроса получает
  отказ «может не показать вопрос… переключи режим или обнови claude» — и на запись файла, и на инструменты agentgraph.
  Отказ проверки остаётся отказом при любой версии.
- **FAIL `space-session: bypassPermissions/dontAsk: свой space.json с папкой /`**: хук отказывал из-за режима, а не
  проверкой. С отказом по режиму ушло и это: проверка идёт первой в каждом режиме (юнит в
  `sessions-server.edit.test.ts` — «корень диска» во всех четырёх).
- **FAIL `session-edit: папка пространств — в permissions.ask`**: ожидание сценария было из первой версии. По решению
  после ревью в `ask` только своё пространство, остальные — `deny`; теперь строки «своё пространство — в
  permissions.ask» и «чужое пространство — в permissions.deny».
- **«не воспроизведено / попыток нет»** (чужое пространство, `tags/`, `SPACES/`, `settings.json`): попытки были, но
  Claude Code отклоняет `Edit`/`Write` по правилу `deny` из `--settings` **до хука**, и лог хука их не видел. Сценарий
  теперь пишет и сами вызовы модели с результатом инструмента (`rawCalls`): такая строка — «отказ правилом deny», `ok`,
  если попытка была, инструмент вернул «File is in a directory that is denied by your permission settings» (текст взят
  из бинарника Claude Code 2.1.285), вопроса не было и файл цел; отказал только хук — `FAIL` «правило deny не
  сработало» (`Bash` держит именно правило). Плюс haiku пропускал шаги из длинного списка — теперь каждый шаг
  отдельным ходом (`perMode` принимает массив). Ещё одна причина пропусков — `Write` в существующий файл без `Read`
  Claude Code отклоняет до хука («File has not been read yet»): `space.json` и `settings.json` теперь шаги
  «Read+Write», а пространство, заведённое после старта, получает новый файл `gamma/LATE.md`.
- **Лимит сессии**: по ходу на шаг выходит 8–9 ходов на режим; `maxBudgetUsd` поднят до 2, режимы без вопросов идут
  первыми, а упёршаяся в лимит сессия даёт строку «пропущено: сессия упёрлась в лимит», а не «режим недоступен».
- **`Bash`**: `cp` в своё в `default`/`acceptEdits` — вопрос; `>` в чужое — не пишется. Вопрос про `acceptEdits`
  закрыт. `cp` в `bypassPermissions` переведён на существующую папку (см. выше).

Какие строки должны стать `ok` после перезапуска:

- `space-session`: `хук записи в --settings`, `своё пространство — в permissions.ask`; для каждого из `default`,
  `acceptEdits`, `bypassPermissions`, `dontAsk` — `своя карта — с вопросом`, `свой space.json, верный — с вопросом`,
  `свой space.json с папкой / — отказ хука до вопроса` (теперь шаг «Read+Write»), `своё .CLAUDE/ в другом регистре —
  с вопросом`,
  `чужое пространство — отказ правилом deny`, `tags/ — отказ правилом deny`, `SPACES/ в другом регистре — отказ
  правилом deny`, `пространство, заведённое после старта — отказ хука`, `новая папка в spaces/ — отказ хука`.
- `session-edit`: `своё пространство — в permissions.ask`, `папка flow — в permissions.ask`, `чужое пространство — в
  permissions.deny`; для каждого из четырёх режимов — `карта своего пространства — с вопросом`, `документ своего
  пространства — с вопросом`, `flow (схема в порядке) — с вопросом`, `flow не по схеме — отказ хука`, `чужое
  пространство — отказ правилом deny`, `settings.json папки настроек — отказ правилом deny`, `Bash > в чужое
  пространство — не пишется`, `Bash cp в своё пространство — не молча` (кроме, возможно, `bypassPermissions` — ниже).
- `ask-modes`: `<режим>: хук ответил ask — claude спрашивает` для всех четырёх; рядом строки `<режим>: без хука
  (контроль)` — `факт` (ожидается: в `bypassPermissions` и `acceptEdits` файл появился без вопроса, в `default` —
  вопрос, в `dontAsk` — отказ без вопроса).
- Останутся «не воспроизведено»: строки `auto` (на haiku режим недоступен; покрыть — `--model` с моделью, где `auto`
  есть, дороже).

## Второй прогон check-sdk-hooks (2026-11-13, `--only space-session,session-edit,ask-modes`) и что поправлено

Итог прогона ($0.88): 70 ok, 7 FAIL, 3 «не воспроизведено» (`auto` на haiku недоступен). Ни один FAIL не означал тихой
записи, кроме одного:

- **`dontAsk`, 6 FAIL** (своя карта, свой `space.json`, своё `.CLAUDE/`, документ, flow): хук ответил `ask`, вопроса не
  было, файл цел. Контроль `ask-modes` (хук `ask` без правила `ask` в `--settings`) вопрос в `dontAsk` показывает —
  значит, отказ без вопроса даёт явное правило `ask`: в `dontAsk` claude превращает его в отказ. Правило `ask` —
  второй рубеж, если хуки выключены, поэтому оно остаётся; **в `dontAsk` хук теперь отказывает сам, с причиной** («в
  режиме dontAsk claude не показывает вопрос… попроси переключить режим»): итог тот же, но модель знает, почему. То же —
  у инструментов agentgraph (`session_new`, `space_*`, `flow_write`, Teamwork).
- **`bypassPermissions: Bash cp в своё пространство`, FAIL — настоящий**: файл записан без вопроса. Под `deny` (как было
  до этой работы) Bash держит правило, под `ask` в bypass — нет. Теперь **хук `PreToolUse` на `Bash`** (`bashDecision`,
  только в `BASH_GUARD_MODES` = `bypassPermissions`): команда упоминает папку своего пространства или папку flow (как
  есть, realpath, `~/…`, `$HOME/…`, `${HOME}/…`, без учёта регистра) или идёт из рабочей папки внутри них — вопрос.
  Эвристика по тексту: путь из переменных или относительный от другой папки не поймает — это граница режима без
  вопросов. В `default`/`acceptEdits` Bash в своё спрашивает сам claude, в `dontAsk` отказывает — там хук команды не
  сверяет; `auto` не измерен (на haiku недоступен) и в форме предлагается — хук там не ставим, чтобы не спрашивать на
  каждую команду с путём пространства. Хук `Bash` — без `onFailure: block`: сбой сервера agentgraph не останавливает
  каждую команду (эвристика — не граница).
- **Одна функция решения.** Решение `PreToolUse` вынесено из `handleHook` в `preToolDecision` (`sessions.ts`), и
  сценарии `check-sdk-hooks.mts` зовут её же (раньше там был свой вызов `editDecision` мимо логики режимов): прогон
  теперь проверяет ровно то, что отвечает сессия.

Какие строки должны стать `ok` после перезапуска `--only space-session,session-edit`:

- `dontAsk: своя карта / свой space.json, верный / своё .CLAUDE/ — отказ хука с причиной (в dontAsk вопрос не показать)`
  и `dontAsk: карта своего пространства / документ / flow (схема в порядке) — отказ хука с причиной`;
- `bypassPermissions: Bash cp в своё пространство — с вопросом` (вопрос хука → `canUseTool`, файл не появится), так же
  `default`/`acceptEdits`; `dontAsk: … — отказ`; `хук Bash в --settings`;
- остальные — как в этом прогоне (`ok`); `auto` — «не воспроизведено».
