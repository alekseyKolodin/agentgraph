# Сессия правит своё пространство и flow — с вопросом пользователю

Решение владельца: «сессия клода должна иметь возможность с разрешения пользователя менять все что угодно в
пространстве/флоу». Запрет на своё пространство и на flow заменён вопросом на каждую правку — вопросом, который
держится в любом режиме, где claude его покажет; где не покажет — отказ. Остальные границы не тронуты.

> **Перед слиянием прогони на настоящем Claude Code (тратит деньги, сам я его не запускал):**
>
> ```
> npx tsx scripts/check-sdk-hooks.mts --only space-session,session-edit,ask-modes
> ```
>
> Сценарии переписаны под новое поведение: `space-session` (сессия в папке пространства), новый `session-edit`
> (обычная сессия с пространством + flow, плюс шаги `Bash`) и новый `ask-modes` (факт: показывает ли claude вопрос хука
> «ask» в каждом режиме — на этом стоит отказ agentgraph в `bypassPermissions`/`dontAsk`), по режимам
> `default, acceptEdits, bypassPermissions, dontAsk, auto`.

## Что спрашивается и где

- **Хук `PreToolUse` записи** (`Edit|Write|MultiEdit|NotebookEdit`) — теперь у каждой сессии, с `onFailure: block` на
  claude 2.1.295+. Решение — `editDecision` в `src/session-edit.ts`, путь по realpath и без учёта регистра, относительный —
  от рабочей папки claude в момент вызова. Своё пространство = выбранное сейчас (`rec.space`) + то, в папке которого
  открыта сессия.
- **`permissions.ask`** в `--settings`: папка своего пространства и папка flow — второй рубеж, если хук не ответил.
- **Хук `PostToolUse` записи** (новый): проверенный файл (`space.json`, карта, состояние, flow) — ещё раз на диске, против
  снимка и цели, посчитанных в `PreToolUse` (пространство могли сменить, пока висел вопрос); сломан — откат на снимок
  (новый файл удаляется вместе с опустевшей папкой flow), причина — модели (`decision: block`); событие `space`
  (`spacePart`)/`flows` в `/api/events`.
- **Расхождение симуляции `Edit`** с Claude Code (кавычки-«ёлочки», CRLF) — не отказ, а вопрос с пометкой «проверю после
  записи»; страхует `PostToolUse`.
- **Flow внутри проекта сессии** (сессия в репо agentgraph, где схема может опережать запущенный сервер): ошибка схемы —
  предупреждение в вопросе, без отката после записи.
- **MCP**: `space_map_write`, `space_state_write`, `space_settings`, `flow_write` — в `ASK_TOOLS` (хук `ask` + правило
  `ask`); не прошедший проверку вызов (`askDetail` → `{ deny }`) отклоняется без вопроса.
- **Режимы**: `default`, `acceptEdits`, `auto` — вопрос (явное `ask` держит его в `acceptEdits` и `auto` — так проверял
  прежний сценарий `space-session`); `plan` — claude правки не делает; `bypassPermissions`, `dontAsk` — **отказ хука**:
  agentgraph не может удержать вопрос (bypass его пропускает, dontAsk отклоняет сам), поэтому правка не становится тихой.
  Форма agentgraph эти режимы и так не предлагает, но они бывают через `defaultMode` пользователя.

### Где agentgraph вопрос не удержит (и что тогда)

- Хуки выключены у пользователя (`disableAllHooks`, политика `allowManagedHooksOnly`): остаётся `permissions.ask` на своё
  пространство и папку flow (вопрос будет, проверки — нет) и deny на чужие пространства, как раньше. Без хуков у сессии не
  работает и всё остальное (контекст, статус).
- Старый claude (< 2.1.295): сбой хука неблокирующий → решает `permissions.ask` (вопрос, проверки до записи нет; после
  записи `PostToolUse` всё равно перепроверит и откатит).
- Пространство, заведённое после старта сессии: правила его не знают — закрывает только хук (как и раньше у сессии в
  папке пространства). Для сессии **без** пространства вся папка пространств закрыта правилом, как было.
- **`Bash`** (`cp`, `sed -i`, `echo >`) хук записи не видит — как и раньше. Что Claude Code делает с файловыми командами
  относительно правил `Edit` (deny/ask) и рабочих папок `--add-dir` — не проверено: своё пространство теперь не под
  deny, а в `--add-dir` (ради карты-памяти), и если `acceptEdits` одобряет `cp`/`sed -i` в рабочих папках без оглядки
  на `ask`, такая правка пройдёт молча. Так же было и до меня у «Сессии в папке» (своё пространство — её cwd). Сценарий
  `session-edit` теперь меряет это шагами 7–8 (`cp` в своё, `>` в чужое). Если подтвердится — варианты в разделе
  «Открытые вопросы».
- Папка чтения пространства, которая **содержит** папку flow (например, сам репозиторий agentgraph при
  `AGENTGRAPH_HOME` не задан), остаётся под deny — flow под ней правятся только `flow_write`.

## Как решено с `space.json`

Оба способа: проверка до вопроса в хуке (текст после записи считается как у Claude Code — `Write` целиком, `Edit`/
`MultiEdit` — ровно одно вхождение или `replace_all`, иначе отказ «перечитай») + MCP `space_settings` через тот же
`updateSpace`, что и вкладка «Настройки». Почему не только хук после записи: человек не должен подтверждать файл, который
сломает пространство (его `dirs` станут `--add-dir` всех сессий). Почему не только MCP: бриф требует, чтобы файловые
правки тоже работали. Почему ещё и `PostToolUse`: симуляция `Edit` может разойтись с Claude Code (нормализация кавычек),
поэтому сломанный итог откатывается на снимок. Неизменённые `dirs`/`cwd` не перепроверяются (как у API) — удалённая
рабочая папка не мешает поправить заголовок; сломанный `space.json` сессия может починить.

## Flow, который идёт сейчас

Запуск работает со своим снимком спецификации (раннер пишет `flow.yaml` в папку запуска на старте и идёт по нему);
правка файла flow его не трогает. Оговорка — существующее поведение, не новое: блок-вызов (`flow: <имя>`) грузит
вызываемый flow из `flows/` в момент, когда до него дошёл запуск, так что правка **вызываемого** flow посреди
родительского запуска попадёт в ещё не начатый вызов — так же, как правка из редактора flow.

## Решение после ревью

Независимое ревью (`code-reviewer`) нашло главное: в первой версии у claude 2.1.295+ статический deny на чужие
пространства был снят (его заменял хук — чтобы пространство, выбранное на ходу, правилось файлами без перезапуска). Хук
видит только `Edit`/`Write`/`MultiEdit`/`NotebookEdit`; если Claude Code сверяет файловые команды `Bash` с правилами
`Edit`, это ослабило бы закрытие чужих пространств. Бриф требует их не ослаблять — **deny на чужие пространства
возвращён при любой версии**, а пространство на ходу правится инструментами `space_*` сразу и файлами после
«Перезапустить». Это осознанный компромисс с пунктом брифа «в том числе выбранное на ходу»: файлы `.claude/` и прочие
файлы папки пространства на ходу — только после «Перезапустить» (одна кнопка в `⋯`; она же грузит карту в память).

Исправлено по ревью: подделка `history`/`migratedFrom`/`createdAt` в `space.json` (открыла бы чужие артефакты всем
сессиям пространства) — теперь отказ; повторная проверка после записи сверяет папки со снимком, а не с уже записанным
файлом; цель и снимок хранятся вместе (смена пространства во время вопроса не теряет проверку); ложные отказы симуляции
`Edit` → вопрос с проверкой после записи; `claude.md` в другом регистре — тоже карта; папка настроек = дом/корень/cwd не
считается «служебной»; опустевшая папка flow после отката удаляется; UI не затирает начатую правку, если она появилась,
пока шёл запрос, и не пугает несохранённую карту правкой документа (`spacePart` в событии); текст «идущие запуски
работают со своим снимком» исправлен на точный; тесты на всё это, на папку команд по относительному пути и в другом
регистре, на `AGENTGRAPH_CONFIG_DIR=~`; контрольный сценарий `ask-modes` и шаги `Bash` в `check-sdk-hooks.mts`.

Не исправлено, описано: `Bash` (см. выше); `space_map_write` пишет карту без базы (`mapBase`) — вопрос показывает только
размеры, правка из UI между чтением и вызовом затрётся (у файловой правки это ловит сам Claude Code — «файл изменён
после чтения»); экран открытого flow (`/flow/<имя>`) правку сессии не замечает, и сохранение из редактора без базы её
перезапишет — как и любую внешнюю правку flow сейчас.

## Открытые вопросы

- Если `check-sdk-hooks` покажет, что `Bash cp` в своё пространство в `acceptEdits` проходит молча: либо убрать папку
  пространства из `--add-dir` (карта тогда придёт строкой «прочитай», а не памятью), либо хук `PreToolUse` на `Bash`,
  который спрашивает, когда команда упоминает папку пространств или flow (эвристика по строке команды).
- Если `ask-modes` покажет, что claude в `bypassPermissions` всё же показывает вопрос хука, отказ в этом режиме (и для
  `session_new`/инструментов Teamwork) можно снять.

## Что не проверено

- Поведение настоящего Claude Code: держит ли он `ask` хука/правила в `auto`, что делает с `ask` в `bypassPermissions`
  (мы там отказываем сами), применяет ли `deny` раньше хука — это проверяют сценарии `check-sdk-hooks.mts`
  `space-session` и `session-edit` (**не запускались**).
- Совпадение симуляции `Edit` с Claude Code на кавычках-«ёлочках» и `\r\n` (страховка — откат после записи).
- Открытый в редакторе flow (экран `/flow/<имя>`) после правки сессией сам не перечитывается — обновляется список flow.
  Открытый документ во вкладке «Документы» тоже не перечитывается (список документов — да).
- Правки пространства через API другой вкладки по-прежнему событий не шлют (событие — только от сессий).
