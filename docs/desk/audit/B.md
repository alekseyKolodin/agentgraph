# B. Код: ревью MR с агентом и задача Jira до MR

## 1. Сценарии

### 1.1 Ревью чужого MR с агентом

**Шаги (по дням):** день 1 — завести рутину GitLab/GitHub «MR на ревью у меня» → flow ревью → ответ в MR. Каждый день: пришёл MR → агент сделал первое ревью → узнать, что готово → открыть MR. Через 1–2 дня автор ответил / допушил → «теперь мне самому» → MR смержен → дело закрыто.

**Что есть:**
- Источник `review`: MR/PR, где я ревьюер, только `state=opened` — `src/routines/sources/forge.ts:62`, GitHub `review-requested:me` — `forge.ts:128`.
- id события `review:<url>` — `forge.ts:65,129`: **одно событие на MR за всю жизнь**. Новые коммиты, повторный запрос ревью, ответ автора — новых событий не дают (дедуп по `seen` — `src/routines/engine.ts:417-425`).
- `comment` — только к **моим** MR (`author_username=me`, `forge.ts:77-87`; GitHub `author:me`, `forge.ts:134-146`). К чужому MR, где я оставил замечания, комментарии не читаются.
- `mention` — GitLab todos `action=mentioned` (`forge.ts:68`); GitHub `mentions:me` с id `mention:<url>` (`forge.ts:131-132`) — снова одно событие на PR, второе упоминание в том же PR не придёт.
- Событий «MR обновлён», «ответили на мой комментарий», «смержен», «закрыт» — **не нашёл** ни в forge.ts, ни в attention.ts (в `src/` `merged` есть только у Teamwork: `src/teamwork-status.ts:82,103-113`).
- Запуск по событию: `startRoutineRun` — `src/server.ts:299-335`. `source: { type: 'routine', key: <slug рутины> }` (`server.ts:329`) — запуск **не помнит MR как источник** (`type: 'mr'`). worktree рутины — новая ветка `routine/<slug>-<время>-…` от base (`server.ts:322`), а не ветка MR: агент сам должен вытягивать ветку MR.
- «Агент закончил»: системное уведомление на конец любого запуска «flow: запуск завершён» — `src/server.ts:1422`, `2187-2198`, клик → `/run/<id>`; при `reply.draft` — карточка «ответ готов» в ожиданиях на Главной (`engine.ts:722-743`, `web/src/screens/home/RoutineWaits.tsx`). В уведомлении — имя flow, а не «ревью !123 готово».
- Ответ в источник — один общий комментарий (GitLab `notes`, GitHub `issues/<n>/comments`) — `forge.ts:91-96,150-154`; inline-замечаний к строкам/review нет.
- «Review» на Главной — это **разбор сессий** «не доделано» (`web/src/screens/home/Review.tsx:1-5`), к ревью MR отношения не имеет.
- «MR · нужно внимание» на Главной — только **мои** MR: упал CI, неотвеченные обсуждения, конфликты (`src/attention.ts:15-29,90`). Чужие MR на ревью туда не попадают. Скрыть/«просмотрено» нет (`web/src/screens/home/Attention.tsx`).
- «Код» (`web/src/screens/code/CodeScreen.tsx:32`) — тот же `Dash`: списки MR проекта, «Запустить…»; связанные запуски по `source.type==='mr'` или ветке (`web/src/lib/dash.ts:32-38`) — запуски рутин сюда **не привяжутся** (тип `routine`, ветка `routine/…`).

**Что добавит центр дел:** карточку «Ревью !123» в «Новое/В работе», «агент закончил» как смену состояния, «автор ответил → в план», «смержен → готово».

**Где рвётся:**
- Нет событий, на которых держится движение дела: обновление MR, ответ автора на мой тред в чужом MR, merged/closed. Строка правила «вернуть в план / закрыть, когда MR смержен» не на что повесить.
- Запуск рутины не связан с MR (тип `routine`) — карточка не найдёт «свой» запуск и наоборот; в «Коде» у MR чипа запуска не будет.
- Ревью идёт не в ветке MR.

**Оценка:** первое ревью — частично (запуск и уведомление есть); «ответили / обновлён / смержен» — не закрыто.

### 1.2 Мой MR (обратная сторона ревью)

- Комментарии к моим MR — по событию на каждую заметку (`forge.ts:85`, id `comment:<p>!<iid>:<note>`): 5 замечаний ревьюера = 5 событий = до 5 запусков, если нет `when.check` с дублем (`engine.ts:466-477`) или лимитов. Склейки «пачка комментариев от одного ревью» нет.
- Свои комментарии отсеиваются `isSelf` (`forge.ts:196`, `engine.ts:427-434`).
- Attention видит «ждут ответа» по discussions (`attention.ts:16-21`) — это уже почти «твой ход» по своему MR, но живёт отдельно от рутин и только на Главной, кэш 60 с в памяти (`attention.ts:36-62`).

**Оценка:** частично.

### 1.3 Задача Jira от назначения до MR

**Шаги:** назначили → увидел → взял (flow или сессия) → ветка → MR → статус в Jira.

**Что есть:**
- Увидел: «Код» → Jira, пресеты `sprint`/`mine` и свой JQL (`src/jira.ts:10-13`, `src/integrations.ts:64-75`), до 50 задач, без отметки «новое».
- Рутина Jira: событие = задача с новым `updated`, id `<key>@<updated>` (`src/routines/sources/jira.ts:84-93`). «Назначили на меня» отдельно не различается: любое изменение задачи (комментарий, статус, правка описания, моя же смена статуса в Jira) — новое событие. Полей «что поменялось / кто назначил / assignee» в событии нет (`jira.ts:91`). Первый опрос только запоминает (`engine.ts:436`) — задачи, назначенные до подключения, событий не дадут.
- Взял в работу: «Запустить…» → `POST /api/intake` (`integrations.ts:131-139`) → форма запуска с текстом задачи (`src/intake.ts:51-64`), источник `type:'jira'` (`intake.ts:62`). Worktree из формы: имя = ключ задачи, если ветка не задана (`web/src/lib/run-form.ts:122-129`). Запуск — только flow; **сессию из задачи Jira не начать** (в `Dash.tsx`/`FlowPicker.tsx` сессий нет; у сессий есть связь только с Teamwork — `src/sessions-server.ts:476-534`).
- Связь задача→запуски: `runsForJira` по `source.key` (`web/src/lib/dash.ts:29`). Задача→ветка→MR: связи нет; только обратная догадка — ключ из заголовка/ветки MR в анкету (`intake.ts:79`). У строки задачи Jira нет её ветки и MR.
- Статус в Jira: клиент умеет `myself/search/issue` (`src/jira.ts:30-34`); перехода статуса (transition) **нет**. Ответ рутины в Jira — только комментарий (`sources/jira.ts:103-120`).
- Прецедент полного цикла есть, но только для Teamwork: старт → «В работе», запуск done → «Ревью», PR открыт → «Ревью», смержен → «Готово», опрос PR раз в 2 мин (`src/teamwork-status.ts:1-8,60-87`).

**Где разработчик теряет нить:**
1. После запуска flow: ветка, сделанная агентом (не worktree формы), и открытый MR никак не привязаны к задаче.
2. Работа в сессии — без привязки к задаче Jira вообще.
3. MR открыт → в «Коде» он во вкладке проекта, задача — во вкладке Jira; связаны только глазами.
4. MR смержен → задача в Jira остаётся «In Progress», приложение статус не двигает и не напоминает.

**Оценка:** частично (увидеть и запустить); ветка/MR/статус — не закрыто.

## 2. Через месяц

- **Ревью:** по одному запуску на MR (повторов нет — но и «второго круга» нет). За 30 дней — десятки запусков `source: routine`, в списке запусков их не отличить по MR, только по заголовку события (`server.ts:329`). Ожидания `reply`-черновиков копятся на Главной, если не отвечать; «Не сейчас» прячет (`engine.ts:753-757`), но не закрывает.
- **Свои MR:** комментарии дают поток событий по одному на заметку — главный источник шума рутин.
- **Jira:** каждое обновление задачи — новое событие; задача, которую неделю обсуждают, даёт десяток событий. Без `when.check` (дубли, haiku) или `match.key` — повторные запуски по одной задаче. Курсор Jira — 300 задач (`sources/jira.ts:95-98`).
- **Отличить просмотренное:** нигде нет отметки «я посмотрел» у MR или задачи — ни в «Коде», ни в Attention. Attention пересчитывается из GitLab каждый раз; MR, где я ответил, исчезает сам (последняя реплика моя, `attention.ts:19-20`) — это единственный «сам ушёл».
- **`seen` = FIFO на 2000 id** (`src/routines/store.ts:15,180-186`): долго открытый MR/задача, чей id вытеснен новыми комментариями, придёт снова как новое событие → повторный запуск через несколько недель. Мелочь, но месячная.
- **Журнал рутин** — 2000 строк на рутину (`store.ts:22`), история источника — 50 событий (`store.ts:17`).
- **Worktree рутин** `routine/<slug>-…` по одному на событие (`server.ts:322`) — копятся на диске и в `git branch`, чистить руками.
- Закрытые/смерженные MR из источника просто пропадают (опрос только opened) — для движка это молчание, а не событие.

## 4. Дубли и пересечения с центром дел

- **«MR · нужно внимание» (`attention.ts`, `Attention.tsx`)** — уже готовый «твой ход по своему MR» (CI, ответы, конфликты). Должен стать источником дел (вид «Ревью/Своё»), а блок на Главной — лишним.
- **Teamwork-автоматика статусов (`teamwork-status.ts`)** — тот же автомат «взял → в работе → ревью → смержен → готово», что нужен центру дел. Два автомата для «задача + PR» — дубль; логику prPatch/опроса PR стоит вынести общей.
- **Ожидания рутин на Главной (`RoutineWaits.tsx`)** — «агент закончил ревью, ответ ждёт» = колонка «В плане»/«Новое» центра дел; две очереди «твоего хода».
- **«Код» (`CodeScreen.tsx` / `Dash`)** — списки Jira/MR остаются как обзор и точка «Запустить…», но «что из этого моё сейчас» уходит в доску; `RelatedRuns` → в карточку дела.
- **«Review» на Главной (`Review.tsx`, разбор сессий)** — пересекается с источником «обход проектов / висящие сессии»; к ревью MR не относится, название путает рядом с видом дела «Ревью».
- **Подбор flow для MR (`suggestFlows`, `attention.ts:171`)** — пригодится карточке дела («чем чинить»), отдельной строкой на Главной не нужен.
