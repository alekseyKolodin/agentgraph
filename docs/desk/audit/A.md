# A. Ритм дня и пять проектов

## 1. Сценарии

### 1.1 Утро: открыл приложение

**Шаги.** Открыл → смотрит на Главную → решает, с чего начать → идёт в MR / сессию / запуск.

**Что есть сейчас** (порядок блоков сверху вниз, `web/src/screens/home/HomeScreen.tsx:97-155`):
1. `Start`: «с чего начать» показывается только если ещё не было ни одного запуска и ни одной сессии (`HomeScreen.tsx:81,99`). Это первый день, а не «с чего начать сегодня».
2. `RoutineHome`: карточки ожиданий рутин и строка «догнать», то есть что пришло, пока приложение было закрыто (`RoutineWaits.tsx:19-45`). Для утра это самое ценное.
3. «Ждёт тебя»: вопросы агентов из идущих запусков и живые сессии терминала, где ход за тобой (`HomeScreen.tsx:101-121`, `lib/sessions.ts:67-74`).
4. «Идут»: запуски и работающие сессии (`HomeScreen.tsx:122-128`).
5. «Не доделано»: разбор сессий за 14 дней (не больше 15 сессий), только по кнопке и платно (sonnet) (`Review.tsx:81-133`, `src/session-review.ts:23,25`). Скрытые строки и результат хранятся в localStorage (`Review.tsx:18,25-28`).
6. «Мои задачи» Teamwork: задачи в активных спринтах (`HomeScreen.tsx:130-134`, `screens/teamwork/MyTasks.tsx:18-27`).
7. «MR · нужно внимание»: только **свои** открытые MR, у которых упал CI, есть ответы в обсуждениях или конфликты. Подсказка flow от haiku (`Attention.tsx:1-3,56`). MR, где тебя позвали ревьюером, здесь нет.
8. Справа «События»: вопросы, паузы и концы **только запусков flow** (`Feed.tsx:1-3`, `src/server.ts:2287-2303`). Сессий, рутин и MR в ленте нет.

На рельсе сайдбара счётчик значка «Главная» = вопросы агентов + ожидания рутин (`components/shell/Sidebar.tsx:229-231,269`). «Сейчас» в панели — живые запуски и сессии (`Sidebar.tsx:67-131`).

**Понимает ли «здесь всё».** Нет:
- Задачи Jira и MR целиком лежат в «Код» (`HomeScreen.tsx:5`, `screens/code/CodeScreen.tsx:1-3`).
- Чужие MR на ревью видны только через рутину.
- Сверки «все источники проверены» нет: Attention пишет «— ничего не нужно» только про свои MR (`Attention.tsx:58-64`).
- Ни один блок не выбирает «одно первое дело». Блоки отсортированы по типу источника, а не по важности.
- У каждого блока свой счётчик и своё «пусто», общего «N дел» нет. Главная — набор лент по источникам (рутины / агенты / сессии / Teamwork / MR), а не список дел.

**Что добавит центр дел.** Одна доска по состоянию, «Начни с этого», сверка «N из N источников», срез по проектам. Он закрывает ровно то, чего нет: единый список, приоритет и полноту.

**Заменить, встроить или дублировать.** Предлагаю так: доска становится **Главной**, а то, что у Главной «живое», остаётся полосой над доской.
- **Остаётся над доской** — то, что требует ответа за секунды и не является делом: карточки ожиданий рутин и «догнать»; вопросы агентов (QuestionCard отвечается прямо на месте); «Идут» — компактной строкой или только в «Сейчас» сайдбара (там это уже есть, дубль).
- **Уезжает в доску карточками:**
  - Attention, свои MR (вид «Ревью» / «Своё»; «CI упал» и «ждут ответа» — это «почему твой ход»).
  - «Мои задачи» Teamwork (вид «Jira» / «Своё»).
  - «Не доделано» (вид «Забытое»; строку с «Осталось» и «С чего продолжить» перенести в карточку).
  - Сессии «ждёт тебя» с открытым вопросом (источник «обход проектов»).
- **Лента «События»** остаётся историей, но сейчас она только про запуски. Её стоит либо расширить на дела, либо свернуть.
- **Риск дубля:** если доску сделать отдельным разделом рядом с Главной, у одного MR будет три места (Главная/Attention, «Код», доска), а у сессии четыре (Главная, «Сейчас», «Не доделано», доска).

**Оценка: частично.** Утренний «что нового» есть (рутины, вопросы). «Всё ли проверено» и «с чего начать» нет.

### 1.2 Конец дня: где остановился

**Шаги.** Закрывает сессии → хочет, чтобы завтра было видно, на чём встал в каждом проекте.

**Что есть:**
- STATE.md пространства («где мы сейчас») переписывает сессия состояния после успешного запуска и при выходе из сессии терминала (`src/space-state.ts:1-4`, `src/spaces.ts:5`). Первая строка STATE.md — превью в списке пространств (`src/spaces.ts:263-267`, `web/src/lib/spaces.ts:28`). Это настоящее «где остановился», но **только для работы в пространстве**.
- «Не доделано»: тот же ответ по сессиям, но по кнопке, платно и с горизонтом 14 дней (`Review.tsx:92`, `session-review.ts:23`).
- Сессия, которую приложение закрыло на ходу, помечается `statePending: 'app-closed'` и обновит состояние (`src/sessions-server.ts:286-291`).

**Где рвётся:**
- Сессия или запуск без пространства не получают STATE. Для них «где остановился» есть только в «Не доделано» по кнопке.
- Незакоммиченных изменений в репозиториях проектов никто не смотрит. `git status --porcelain` вызывается только для репо Teamwork и для обновления (`src/teamwork-repo.ts:602`, `src/update.ts:101`). Для проектов из «Подключений» не нашёл. Ветки есть, ahead и behind тоже (`src/git.ts:117,462-464`).
- Нет действия «закрыть день» и сводки «что сделано сегодня».

**Что добавит центр дел.** Обход пяти проектов: висящие сессии с открытым вопросом и незакоммиченные ветки как карточки «Забытое». Срез «где остановился» по проектам.

**Оценка: частично.** Внутри пространств закрыто, вне их не закрыто. Незакоммиченное не закрыто.

### 1.3 Переключение между пятью проектами

**Шаги.** Перейти от проекта A к B → увидеть, где B стоит → открыть сессию или запустить flow там.

**Что есть:**
- Пространства (`/spaces`): карта, состояние, документы, папки, знания, сессии и запуски пространства колонкой (`screens/spaces/SpacesScreen.tsx:1-5`). Список отсортирован по последней работе (`web/src/lib/spaces.ts:108`), есть поиск (`lib/spaces.ts:21-25`) и счётчики сессий, запусков и идущих (`src/spaces.ts:1234-1272`).
- Быстрая сессия ⌘N: закреплённые наборы «пространство + папки + теги» (`components/shell/QuickSession.tsx:1-3,15`). Это фактически переключатель проектов для сессий.
- «Предложить пространства»: haiku раскладывает работу без пространства по группам (`screens/spaces/GroupsPanel.tsx:1-3`).

**Единой сущности «проект» нет.** Слово «проект» значит четыре разных вещи:

| Что | Ключ | Где |
|---|---|---|
| Проект «Подключений» (git-репо для MR, Jira, веток) | путь корня репо | `src/projects.ts:8,11-23` (добавляются сами из cwd запусков) |
| «Проект» в списке запусков сайдбара | `r.project \|\| r.cwd` (корень git, worktree сворачивается к нему) | `web/src/lib/runs.ts:15,86`, `src/server.ts:2307-2320` |
| Пространство («фича или проект») | slug | `src/spaces.ts:1-8` |
| Проект Teamwork | team/slug, привязка к пространству в `local.json → projectSpaces` | `src/api-types.ts:1617,1645,1698` |

Из-за этого:
- Сайдбар группирует **запуски по папке репо** (`RunList.tsx:1-3`, `lib/runs.ts:86`), а **сессии по пространству** (`lib/session-history.ts:10,38`). Один проект попадает в две разные группы с разными подписями.
- На Главной запуск подписан папкой (`HomeRuns.tsx:31`), сессия пространством (`lib/sessions.ts:78`), MR именем проекта «Подключений» (`Attention.tsx:100`). Лента не подписана никак (`Feed.tsx:83`).
- Рутина ссылается на `run.space` и `run.cwd` раздельно (`src/routines/types.ts:196-198`).
- Связи «пространство ↔ репо „Подключений“» нет: у пространства есть `cwd`/`dirs` (`spaces.ts:43`, `spaceWorkdirOf` в `spaces.ts:1254`), но MR и Jira к пространству не привязаны.

**Что добавит центр дел.** В концепте «проект» — поле карточки и срез над доской. Но в коде нет ключа, к которому его привязать.

**Оценка: частично для сессий (пространство + ⌘N), не закрыто для «одного проекта во всех разделах».**

### 1.4 Месячный горизонт (30 дней, сотни запусков и сессий)

**Что есть для объёма:**
- **Запуски:** поиск, фильтр по статусу, группы по проектам, «ещё N» (10 в группе, 40 без групп), скрыть и удалить по одному (`lib/runs.ts:12-13,72-94`, `RunList.tsx:1-3`). Массового «скрыть все готовые» или «удалить старше N» не нашёл.
- **Сессии:** группы по пространству по 5 штук с «ещё N» (`lib/session-history.ts:7,45`). **Поиска нет** ни в списке сайдбара, ни в таблице «Все сессии» (`SessionsScreen.tsx:75-77,356-369`: таблица всех сессий без фильтра и без страниц). Удаление по одной со страницы сессии (`SessionScreen.tsx:79-85`), на сервере `remove` (`src/sessions-server.ts:791-798`). Сессии с диска читаются все (`sessions-server.ts:269-310`).
- **Лента:** последние 50 запусков плюс идущие, до 80 событий, на экране 20 (`server.ts:2287-2293`, `src/feed.ts:13`, `lib/feed.ts:7`).
- **Пространства:** удалить можно, архива нет (`spaces.ts:631`). История состояния — 20 запусков и 10 сессий (`spaces.ts:51-52`).
- **Автоочистки или архива запусков и сессий по возрасту не нашёл** (grep prune/retention/archive по `src/` — только `archived` у проектов Teamwork, `api-types.ts:1544`).

**Что тонет:**
- Запуски от рутин. Их много, они ложатся в общий список и в ленту наравне с ручными. Отдельного фильтра «от рутины» в RunList не нашёл, есть только статусы.
- Завершённые сессии без пространства копятся одной группой «без пространства» (`session-history.ts:49`).
- Ссылки на сессии и запуски на карточках доски через месяц будут вести в эти списки, а там нечем искать.

**Оценка: не закрыто** для сессий (ни поиска, ни очистки), **частично** для запусков (поиск есть, очистки нет).

## 2. Как это живёт через месяц

- **Копится:**
  - Сессии: все с диска, без поиска.
  - Запуски: от рутин особенно.
  - Пространства: «предложить пространства» плодит новые, архива нет.
  - Скрытые строки «Не доделано» в localStorage одной вкладки.
  - `hiddenDirs`, закреплённые наборы ⌘N.
- **Устаревает:**
  - Разбор «Не доделано»: помечается «после разбора были ходы» (`Review.tsx:161`), но сам не обновляется.
  - STATE.md пространств, где давно не работали: превью в списке выглядит актуальным, дата есть только в мете.
  - Проекты «Подключений», подхваченные из cwd разовых запусков (`projects.ts:11-23`): скрываются только руками.
- **Шумит:**
  - «Ждёт тебя»: любая живая сессия в простое считается «ждёт» (`lib/sessions.ts:69-71`; сайдбар прямо пишет, что такая сессия «ждёт человека всегда», `Sidebar.tsx:105`). При пяти проектах это пять вечных «ждёт».
  - Лента: каждый запуск рутины.
  - Счётчик на рельсе.
  - Предел 6 живых сессий (`src/sessions.ts:94`) при пяти проектах почти исчерпан.
- **Чистить руками:** запуски (скрыть или удалить по одному), сессии (удалить по одной со страницы), пространства (удалить), проекты «Подключений» (убрать).

## 4. Дубли и пересечения с центром дел

- **Attention «MR · нужно внимание»** → карточки «Своё/Ревью» с «почему твой ход» (CI, ответы, конфликты). Блок на Главной лишний. Подсказку flow (`Attention.tsx:103-117`) перенести на карточку.
- **«Мои задачи» Teamwork** → карточки. Статус колонки Teamwork и колонка доски — два состояния одной задачи, их нужно согласовать (что главнее).
- **«Не доделано»** — почти готовый источник «Забытое»: verdict, «осталось», «с чего продолжить», «продолжить». Как отдельный блок с кнопкой разбора он лишний, его скрытия в localStorage заменяет закрытие дела.
- **«Ждёт тебя» → сессии** пересекается с источником «висящие сессии» доски и с «Сейчас» сайдбара (три места).
- **«Идут»** на Главной полностью дублирует «Сейчас» в сайдбаре (`Sidebar.tsx:67-101`).
- **Ожидания рутин и «догнать»** — не дела, а решения на секунды. Их место над доской, но «Не сейчас» у ожидания (`HomeScreen.tsx:75`) по смыслу совпадает с колонкой «В плане» или «Ждёт других». Нужно правило, когда ожидание становится карточкой.
- **«Код»** (все Jira, MR, ветки) остаётся каталогом. Доска показывает только то, где твой ход.
- **Срез «пять проектов»** доски пересекается со списком пространств (превью STATE.md, счётчики, последняя работа). Это одни данные, нужен один компонент.
- **Сверка источников** пересекается с журналом рутин (когда смотрела, сколько нашла). Брать оттуда, а не вести второй учёт.
