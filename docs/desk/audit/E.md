### 1.2 Первая неделя: подключение источников и первые рутины

**Сколько шагов до «доска утром показывает моё»** (по коду, для 4 источников концепта):
1. «Подключения»: Jira — адрес, email, API-токен (`src/integrations.ts:42-59`, `docs/GETTING_STARTED.md:207`).
2. `glab auth login` в терминале — вне приложения (`docs/GETTING_STARTED.md:208`).
3. Проекты подхватываются только из cwd прошлых запусков (`src/projects.ts:17-30`). До первого запуска в проекте их нужно добавить руками в «Подключениях».
4. Рутины → «Подключить сервис» → GitLab. Источник берёт `glab`, а Jira — токен из «Подключений» (`src/routines/sources/forge.ts:3,52-58`, `src/routines/sources/jira.ts:1-3,35`). Повторно вводить не нужно, но шаг отдельный.
5. Собрать flow ревью MR / разбора Jira / встречи → дела. Готовых нет (см. 1.1).
6. Новая рутина × 4: источник, условия, flow, пространство, папка, когда ждать, куда сообщать. Сохраняется черновиком, потом включается (`README.md:94-98`).
7. Fireflies — рецепт `templates/sources/fireflies.yaml` + ключ в `secrets.json`.
8. «Обход пяти проектов» (висящие сессии, незакоммиченные ветки): источника такого вида нет. Он делается только своей командой (`src/routines/command.ts`) или расписанием и flow.
9. В каждую рутину — строка «Завести дело…» (концепт).

Итого ≈ 15–20 действий и 3–4 своих flow. Без них доска пустая.

**Что уже даёт «моё» без рутин.** Главная уже сама показывает:
- «Мои MR: нужно внимание» — CI упал, обсуждение ждёт ответа, конфликт: `src/attention.ts:1`, `docs/GETTING_STARTED.md:212-217`;
- «Не доделано» — разбор сессий моделью по кнопке, sonnet, за 14 дней, не больше 15 сессий: `src/session-review.ts:17-25`, `web/src/screens/home/Review.tsx:1-5`;
- «Мои задачи» Teamwork: `HomeScreen.tsx:130-134`.

Это уже полдоски, но без колонок и без «почему мой ход» одной строкой.

**Где рвётся.**
- **Утро после закрытого ноутбука.** Рутины работают, только пока открыт сервер (`docs/routines/SPEC.md:37`). То, что пришло, пока приложение было закрыто, не запускается: оно копится в «Догнать» и ждёт клика (`src/routines/engine.ts:447-450,805-826`, `SPEC.md:38-41`). Пропущенное расписание — тоже строка «догнать» (`engine.ts:859-880`). Значит, «доска утром показывает моё» без клика не выполняется: утром сначала нужно нажать «Догнать» по каждой рутине.
- Первый опрос нового источника только запоминает «уже видено» (`engine.ts:435-436`). Уже открытые MR и назначенные задачи на момент подключения делами не станут. Для центра дел это блокер: в первый день на доске будет пусто, хотя MR на ревью висят.

**Оценка:** не закрыто.

### 1.6 Новый (шестой) проект

- «Проект» в коде означает три разные вещи:
  - git-репо в «Подключениях» для MR и веток — `src/projects.ts:1,17`;
  - пространство — фича, `src/spaces.ts`;
  - проект Teamwork — фича в репо команды, `docs/teamwork/spec.md:49`.
- Срез концепта «по пяти проектам» не говорит, к какому из трёх он относится.
- Шестой репо появляется в «Подключениях» сам после первого запуска в его папке (`src/projects.ts:17-30`) или добавляется руками. Убранный обратно не возвращается (`hiddenProjects`, `projects.ts:12`).
- Источник GitLab без поля `project` смотрит весь хост (`src/routines/sources/forge.ts:18`). MR шестого проекта придут сами, а дела по ним — без привязки к проекту, если рутина не ставит его явно.
- Обход «висящие сессии и ветки» по проектам — своя команда; список пяти проектов зашит в ней, а не берётся из «Подключений».

**Оценка:** частично.

### 1.7 Teamwork

**Что есть.**
- Статусы задач: `todo | in_progress | review | done` (`docs/teamwork/spec.md:133`). Автопереходы только вперёд: начал → «В работе», запуск done → «Ревью», PR открыт → «Ревью», смержен → «Готово» (`spec.md:513-530`, `src/teamwork-status.ts:24,79-87`).
- «Мои задачи» на Главной: только **активный спринт** и только `assignee == я` по `git config user.email` (`src/teamwork-server.ts:267-296`, `web/src/screens/teamwork/MyTasks.tsx:1-4`). Задача, назначенная мне в бэклоге или в планируемом спринте, не видна.
- «Ждёт других» в Teamwork — только `blockedBy` («ждёт PAY-3»: `MyTasks.tsx:49`) и бейдж «запуск ждёт ответа» (`MyTasks.tsx:42,64`). Поля «ревьюер» нет (не нашёл).
- Задача от коллеги: назначение приходит pull'ом раз в 30 с или 5 мин (`src/teamwork-server.ts:39`). Событие `team` только обновляет экраны (`src/server.ts:370`). В ленту и уведомления оно не попадает (`src/feed.ts:23-32` — только запуски). Уведомления об изменениях от коллег явно вне первой версии (`spec.md:677`). Комментарии коллег — тоже без сигнала.
- У рутин нет источника Teamwork (`src/routines/sources/index.ts:5-14`), поэтому строку «Завести дело» на назначение задачи повесить не на что.
- Сессия из задачи получает `team_task_update` и `team_doc_write` (`src/sessions-mcp.ts:6-7,30`) — то место, куда ляжет «завести дело».

**«Мои задачи» и дела центра — один список или два?** Сейчас это будут два. «Мои задачи» Teamwork — отдельный блок Главной со своим статусом (колонки команды), центр дел — свои 5 колонок. Соответствие почти один к одному:

| Teamwork | Центр дел |
|---|---|
| todo | В плане |
| in_progress | В работе |
| review | Ждёт других |
| done | Готово |

Новой задачи («Новое») в Teamwork нет. Если держать оба, одна и та же задача будет показана дважды с разными статусами, и двигать её придётся в двух местах.

**Что должно слиться.** Задача Teamwork с `assignee == я` — это дело вида «Своё» или «Teamwork». Его колонку центр берёт из `status` задачи и не хранит свою. «Ждёт других» = `review` или непустой `blockedBy`. «Новое» = назначили, а я ещё не открыл (нужен признак «видел»). «Мои задачи» на Главной становится не нужен.

**Оценка:** частично.

- **Оценка:** частично. Состояние фичи копится, знания по виду работы — нет.

## 2. Как это живёт через месяц

- **Копится.** Сотни запусков: каждое срабатывание рутины ревью — отдельный запуск в общем списке, без признака «от рутины» в фильтре. Десятки сессий в таблице без поиска. Карточки «Не сейчас», которые никогда не истекают. Пространства законченных фич без статуса «закрыто».
- **Устаревает.**
  - STATE.md пространств, где давно ничего не шло: даты свежести рядом нет (не нашёл).
  - «Не доделано» перестаёт видеть сессии старше 14 дней.
  - Знания-теги не знают, используются ли.
  - Карточки ожидания рутин по MR, который уже смержен, висят.
- **Шумит.** На Главной уже 7 блоков: рутины, «Ждёт тебя», «Идут», «Не доделано», «Мои задачи», «Мои MR», лента. Центр дел станет восьмым, если не заменит их. Лента — 80 записей, отметка «прочитано» только в одном браузере.
- **Чистить руками.** Запуски и сессии — по одному. Пространства — удалять. «Догнать» — по рутине. Отложенные карточки — по одной. Worktree — `git worktree remove` вручную (`docs/GETTING_STARTED.md:209`).

## 4. Дубли и пересечения с центром дел

- **«Мои задачи» Teamwork** (`MyTasks.tsx`) — тот же список дел вида «Teamwork». Слить: колонка дела = `status` задачи (todo / in_progress / review / done → В плане / В работе / Ждёт других / Готово), блок на Главной убрать.
- **«Мои MR: нужно внимание»** (`src/attention.ts`) — те же причины, что и «почему твой ход» у дела Ревью или своего MR (CI, обсуждения, конфликт). Стать источником дел или вычислять «почему сейчас» у карточки, а не жить отдельным блоком.
- **«Не доделано»** (`src/session-review.ts`, `web/src/screens/home/Review.tsx`) — тот же «Забытое» из обхода проектов. Вердикт продолжить / последний шаг / готово естественно ложится в колонки В работе / В плане / Готово. Слить, иначе два разбора сессий с разными ответами.
- **Карточки ожидания рутин и «Догнать»** (`web/src/screens/home/RoutineWaits.tsx`) — по сути дела в «Новое» с кнопкой «Запустить». Без слияния одна вещь будет и карточкой, и делом.
- **«Ждёт тебя» и «Идут» на Главной** — вопросы и паузы запусков и сессий. Это «почему твой ход» у дела, к которому привязан запуск. Оставить строкой у карточки дела, отдельный блок — только для запусков без дела.
- **Раздел «Код» (Jira, MR, ветки)** и Jira-источник рутины — две выборки Jira с разным JQL (`src/integrations.ts`, `src/routines/sources/jira.ts`). Плюс центр — третья. Нужен общий пресет «назначено на меня».
- **Статусы Teamwork по PR** (`src/teamwork-status.ts`) и «дело само ходит: MR смержен → закрылось» — одна и та же автоматика по `gh` / `glab`. Делать один наблюдатель PR на обоих.
- **Лента событий** — после центра это журнал, не входящие.
