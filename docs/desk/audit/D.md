# D. Где делается сама работа: сессии, ветки, flow и запуски

## 1. Сценарии

### 1.1 «Забытое»: висящая сессия с открытым вопросом

**Шаги пользователя.** День 1: открыл 3–4 сессии в разных проектах и одну бросил на вопросе Claude «так делать или иначе?». Вечером закрыл приложение. День 2: ждёт, что на доске будет карточка «Забытое: сессия X ждёт ответа», клик по ней откроет тот же разговор.

**Что уже есть:**
- Статус живой сессии: `starting | working | waiting | ended` (`src/api-types.ts:555`). `waiting` ставят хуки Stop, конец хода и уведомления `permission_prompt / idle_prompt / elicitation_dialog` (`src/sessions.ts:633`, `src/sessions.ts:717-735`). Есть `waitingSince` (`src/api-types.ts:614-615`). Переход working→waiting рассылается: `onSessionWaiting` → лента главной и уведомление (`src/sessions-server.ts:1309-1320`, `src/server.ts:362-366`).
- Последний ответ Claude сохраняется в журнале ходов (`turn.answer` из `last_assistant_message`, `src/sessions.ts:731`; тип `SessionTurn` — `src/space-state.ts:187`).
- «Не доделано» на главной: модель sonnet по кнопке и с ценой заранее разбирает сессии за 14 дней, не больше 15 штук. Вердикт `continue / wrap / done`, плюс поля «что осталось» и «с чего продолжить» (`src/session-review.ts:17-51`, `web/src/screens/home/Review.tsx:1-5`). Результат и скрытые строки лежат только в localStorage (`Review.tsx:17`).
- «Продолжить»: `POST /api/sessions/:id/continue` открывает тот же разговор через `--resume`, а если транскрипта нет — начинает новый (`src/sessions-server.ts:749-769`; `resumable` — `src/api-types.ts:612-613`).

**Что добавит центр дел:** карточку «Забытое» с причиной «Claude спросил и ждёт» и кнопку «Продолжить» прямо на карточке.

**Где рвётся:**
- `waiting` не значит «задан вопрос». Это любой конец хода: Stop ставит `waiting` и после «готово, закоммитил» (`src/sessions.ts:731`). Отличить «ждёт ответа на вопрос» от «просто закончил» может только модель, то есть «Не доделано» по кнопке и за деньги.
- После закрытия приложения статус теряется. Все сессии становятся `ended` с `endedBy: 'app'`, а `waitingSince` бывает только у живой (`src/api-types.ts:595-615`). На следующий день «висящих» сессий в API нет, есть только завершённые.
- Готового детектора «последний ответ — вопрос» без модели не нашёл. Разбор не запускается сам (только по кнопке, `Review.tsx`) и не сохраняется на сервере.
- «Продолжить» с карточки упирается в лимит из 6 живых сессий: ответ 409 `limit` (`src/sessions.ts:94`, `src/sessions-server.ts:755`). Передать первым сообщением «с чего продолжить» нельзя: `continue` принимает только размер терминала (`src/sessions-server.ts:1795-1798`). Сейчас эту строку копируют руками (`Review.tsx:4-5`).
- У сессии нет поля «проект». Есть только `cwd`, `space` и `teamwork` (`src/sessions-server.ts:55-97`). Свести карточку к одному из пяти проектов можно только по `cwd` → `repoRoot`.

**Оценка: частично.** Признак «ждёт» есть только у живой сессии, вопрос от не-вопроса без модели не отличить, продолжение без первого сообщения.

### 1.2 «Забытое»: незакоммиченная ветка в одном из пяти проектов

**Шаги.** По утрам хочется видеть по проектам, где грязный checkout или ветка впереди origin без MR.

**Что уже есть:**
- Список локальных веток: имя, upstream, дата и тема последнего коммита (`src/git.ts:115-126`), плюс worktree (`src/git.ts:128-142`). API — `GET /api/projects/branches` (`src/integrations.ts:110-114`), вкладка «Ветки» в карточке проекта на дашборде с кнопкой запуска flow по ветке (`web/src/screens/home/Dash.tsx:188-253`). Ahead/behind считается только при создании worktree (`src/git.ts:462-464`).
- `git status --porcelain` есть только в обновлении приложения (`src/update.ts:101-113`) и в клоне Teamwork (`src/teamwork-repo.ts:602`). Для проектов пользователя его нет.

**Обход проектов рутиной:**
- Встроенного вида источника «проекты / ветки / сессии» нет. Виды: command, slack, telegram, gitlab, github, jira, rss, folder, email, connector (`src/routines/types.ts:42-46`, `src/routines/sources/`).
- Свой `command` выполняет любую команду через `sh -c` и ждёт JSON (`src/routines/command.ts:1-15`). Белый список для curl действует только для команд, которые придумала модель (`src/routines/sources/draft.ts` → `command-guard.ts:1-3`). Значит, скрипт «обойти 5 репо, напечатать грязные» пользователь пишет сам, и список проектов в нём дублирует настройки.
- Повторно виденные id не запускаются (`src/routines/engine.ts:417-421`, `types.ts:11`). Ветка, которая грязная третий день, событием больше не придёт, а события «ветка стала чистой» нет вовсе. Закрывать такие дела сам по себе источник не умеет.

**Оценка: не закрыто.** Сигнала «грязно / впереди без MR» нет ни в API, ни в источниках.

### 1.3 Как сессия связана с проектом, делом, запуском

- Сессия ↔ запуск: связи нет. В `SessionRecord` нет `runId` или `source` (`src/sessions-server.ts:55-97`). У запуска есть `source` (`jira | mr | branch | teamwork | routine`, `src/api-types.ts:99-105`) и `parent` (`server.ts:2353`), а вида `session` нет.
- Сессия ↔ задача: есть только для Teamwork (`teamwork`, `src/api-types.ts:616-617`; инструменты `team_task_update` и `team_doc_write` — `src/sessions-mcp.ts:178-214`). Это готовый образец того, как может выглядеть связь «сессия из дела».
- Сессия ↔ проект: только `cwd` и `space`. Список сессий не группируется по проекту, а список запусков группируется (`web/src/lib/runs.ts:80-86`).
- Куда ляжет «завести дело» из сессии: в MCP-сервер `agentgraph` (`src/sessions-mcp.ts:65-216`). Сейчас там `knowledge_read`, `space_*`, `flow_write`, `session_new` и инструменты Teamwork. Каждый вызов, кроме `knowledge_read`, подтверждается (`sessions-mcp.ts:7-9`). Инструмента «дело» нет. Добавляется так же, как `team_task_update`: из сессии автоматически берутся `cwd`, `space` и id сессии.

**Оценка: частично.** Механизм есть, связей с делом и запуском нет.

### 1.4 Написание и отладка flow

**Шаги.** Неделя 1: «Новый flow» генерацией из описания, вручную или разовым запуском (`web/src/screens/flow/NewFlowDialog.tsx:1-3`; `src/generate.ts`, `src/flow-ai.ts`). Дальше правка в Builder или YamlEditor, ИИ-правка `/api/flows/:name/edit` (`src/flow-ai.ts:1`) и запуск через RunForm. На паузе нужен ответ, на падении — починка.

**Что уже есть:**
- Пауза и вопросы агента попадают в ленту (`src/feed.ts:17-30`). Ответ — `POST /api/runs/:id/answer` (`server.ts:1155`). Черновик ответа на паузу живёт только в памяти вкладки (`web/src/screens/run/pauseAnswer.ts:1-2`) и при перезагрузке пропадает.
- «Починить и продолжить»: правка flow, повтор итерации и подгрузка из `flows/` (`src/run-fix.ts:1-4`, `FixPanel.tsx:1-3`). Работает **только на паузе** (`web/src/lib/run/view.ts:163-170`).
- Упавший или прерванный запуск продолжается **новым запуском** с первого незавершённого блока, текущей версией flow (`server.ts:965-970`, `view.ts:172-180`). Прерванный (`interrupted`) — это `running` без процесса (`server.ts:2611-2621`).
- Анализ flow по завершённому запуску: sonnet, файл `analysis.json` (`src/run-analysis.ts:1-5`, `Overview.tsx:52`).
- Разовый запуск можно сохранить как flow (`SaveFlowDialog.tsx:1-2`, `server.ts:973-977`).
- «Flow из сессии» сделан только как скилл `.claude/skills/session-to-flow` и инструмент `flow_write`. Кнопки в UI сессии не нашёл. В `~/.claude/skills` скилла нет, поэтому сессии в других проектах его, скорее всего, не видят. При этом сам скилл описывает установку симлинком в `~/.claude/skills` (`SKILL.md:9`).

**Как flow заводит дела:** инструментов у этапа — `KNOWN_TOOLS` (`src/schema.ts:5`), коннекторы, плагины, артефакты и знания (`src/runner.ts:1552-1571`). Инструмента «дело» нет. Встраивать его нужно так же, как `artifactToolsServer` и `knowledgeToolsServer`.

**Запуск упал на полпути — что узнает дело:**
- Статусы `failed | budget_exceeded | max_iterations | aborted | interrupted` (`src/api-types.ts:314`).
- Событие `end` в ленте появляется только при `finishedAt` (`src/feed.ts:31`). У `interrupted` `finishedAt` не ставится (`server.ts:2615-2621`), поэтому, судя по коду, в ленту он не попадает.
- Продолжение получает **новый id** с `parent`. Карточка, привязанная к id запуска, останется на упавшем, если не идти по цепочке `parent`.
- Рутина узнаёт конец запуска (`src/routines/engine.ts:61`, `722`), но только для ответа наружу. Дела, заведённые до падения, ни о чём не узнают.

**Оценка: частично.** Отладка на паузе сильная. После падения — новый запуск без связи с делом. «Flow из сессии» не в UI.

## 2. Через месяц

- **Сессии копятся без конца.** Автоочистки нет. Список — одна таблица, живые сверху, без поиска, фильтров, скрытия и группировки по проектам (`web/src/screens/sessions/SessionsScreen.tsx:352-410`; `list()` — `src/sessions-server.ts:317-321`). Удалить можно только по одной из экрана сессии (`SessionScreen.tsx:80`, `389`). «Ту сессию с прошлой недели» придётся искать глазами по имени (имя берётся из первого сообщения, `src/session-title.ts`). Поиска по транскриптам в приложении нет.
- **«Не доделано» видит только 15 последних сессий за 14 дней** (`session-review.ts:23-25`). Брошенное раньше выпадает молча, остаётся только `skipped`.
- **Запуски копятся без конца.** Есть поиск, фильтр по статусу, группы по проектам, скрытие и удаление по одному (`web/src/components/shell/RunList.tsx:1-4`, `web/src/lib/runs.ts:70-90`). Массовой очистки нет. Лента берёт только 50 последних запусков (`server.ts:2287`), поэтому старые вопросы и паузы из неё выпадают.
- **Версии flow:** свои flow игнорируются git (`.gitignore`: `flows/*`). Истории версий в приложении нет. Есть только снимок `flow.yaml` в папке каждого запуска и `flow.N.yaml` при правке на ходу (`src/runner.ts:191`, `401`). Откатить flow к позапрошлой версии можно, только найдя запуск с нужным снимком.
- **Какие flow реально используются:** в `FlowSummary` нет ни счётчика запусков, ни последнего запуска (`src/api-types.ts:263-278`). Экран flow не показывает свои запуски (`FlowScreen.tsx`). Мусорные flow от генерации так и остаются в списке.
- **Шум:** каждый конец хода любой сессии даёт `waiting`, уведомление и строку в «Ждёт тебя» (`server.ts:362-366`). Если центр дел будет брать «Забытое» из `waiting`, он станет копией этого потока.

## 4. Дубли и пересечения с центром дел

- **«Не доделано» (Review.tsx)** — это готовый источник «Забытое» с вердиктами continue/wrap/done. Он должен стать рутиной-источником доски, а отдельная секция на главной — исчезнуть.
- **«Ждёт тебя» на главной (HomeSessions, лента session)** и «Забытое»: живая ждущая сессия — это «в работе, ход за мной», а не «забытое». Нужно правило, чтобы одна сессия не висела в двух местах.
- **Лента (feed.ts) вопросов и пауз запусков** пересекается с карточками «запуск ждёт ответа». Ленте лучше остаться журналом, а действие держать на карточке.
- **Вкладка «Ветки» дашборда (Dash.tsx)** и срез «где остановился» по пяти проектам — одно и то же. Срез над доской должен её заменить или ссылаться на неё.
- **Ожидания рутин (RoutineWait, kind pause/reply)** и карточки дел запусков — два места для одного «запуск стоит перед блоком».
- **Teamwork `team_task_update`** — параллельная модель «сессия двигает задачу». Нужно решить, заводит ли сессия из задачи Teamwork ещё и дело, или задача Teamwork и есть дело.
