Источники

Источник — это проверка, которая возвращает список записей: встречи, письма, заявки, алерты, файлы. agentgraph запускает её раз в несколько минут и помнит, что уже видел. Каждая новая запись становится событием. Так подключается любой сервис, а не только те, что перечислены в примерах. Источник подключают один раз, дальше он доступен любой рутине.

Как подключитьЧто происходитВажно
Описать словами«Новая запись встречи в Fireflies». Агент находит API сервиса, просит ключ, собирает проверку, запускает её и показывает, что нашёл.Основной путь. Перед сохранением видно, какой запрос будет выполняться. Сами проверки идут без модели.
Своя командаЛюбая команда, которая печатает JSON-список записей с id: curl, gh, свой скрипт.Для тех, кто умеет. Этим же способом устроены готовые источники.
Подключение claude.aiВызывается инструмент подключения «список…», новые записи становятся событиями.Ключ не нужен, но подключения доступны только через сессию модели. Каждая проверка тратит лимит, поэтому интервал от 30 минут.
ГотовыеSlack, Telegram, GitLab, GitHub, Jira, почта, RSS, папка на диске. Slack и Telegram внутри держат соединение, поэтому сообщения приходят сразу.Источник — небольшой файл. Свой можно отдать коллеге, и он появится у него в готовых.
РасписаниеВнутренний таймер: каждый будний день в 9:30, раз в час.Пока приложение закрыто, время пропускается. После запуска один раз спросит, догнать ли.

Источники работают, пока открыто приложение. Пропущенное за время простоя не запускается само: на главной появляется строка «пришло 9 событий, 2 подходят».

Событие одного вида

Из-за этого триггер универсальный. Что бы ни прислало событие, рутина видит одни и те же поля. Условия, проверка словами и вход flow работают одинаково для Slack, Fireflies и расписания.

# новая встреча в Fireflies.ai → событие source: fireflies # вид: сервис по API id: 01JD… # уже виденные id не запускаются повторно at: 2026-11-17T10:42 title: Планёрка billing # что показать в журнале text: краткое содержание встречи link: ссылка на встречу в Fireflies fields: # ответ сервиса целиком duration: 42 participants: [ … ]
Заголовок и текст известны заранееДля Slack, Telegram, MR и сервисов с готовым шаблоном. В своём запросе ты один раз указываешь, какие поля ответа считать идентификатором, заголовком и текстом.
Условия на поля«название содержит billing» или «длилась дольше 10 минут» решается без модели. Проверка словами нужна, только когда отбор по смыслу.
Полный текст забирает flowВ событии краткое содержание и идентификатор встречи. Полную расшифровку этап flow читает сам, по идентификатору.
Вход flowЗадача flow плюс событие в обёртке данных, тем же wrapData, что и задача из Jira. Агент видит текст события как данные, а не как инструкцию.

Файл правила

Рутина — небольшой YAML, как и flow. Экран создания и редактор пишут его, руками его тоже можно править. Цепочка «таска → фикс» живёт блоками внутри flow, правило только запускает его.

# ~/.agentgraph/routines/bug-from-slack.yaml title: Баг из #bugs → таска и фикс when: source: slack-work match: { channel: bugs, thread: false } check: | # необязательно Это баг-репорт: описано сломанное поведение продукта. Вопросы — не баг. run: flow: bug-to-fix space: billing worktree: new pause_before: [fix] mode: until_pause # suggest | until_pause | auto reply: { to: source, on: [pause, end], draft: true } limits: { usd: 3, per_day: 5, parallel: 1 }
# ~/.agentgraph/routines/weekday-mr-digest.yaml title: Утром сводка по моим MR when: schedule: "30 9 * * 1-5" # будни, 9:30 missed: ask # ask | skip run: flow: mr-digest input: Что в моих MR требует ответа сегодня mode: auto reply: { to: telegram-me, on: [end] } limits: { usd: 0.5 }
Что меняется в ядреИсточники (опрос сервисов по API и через подключения, бот Telegram, опрос Slack, таймер), журнал срабатываний и опция запуска pauseBefore в раннере: пауза перед блоком задаётся снаружи, сам flow не меняется.
Источник — тоже файлЛежит в ~/.agentgraph/sources: команда или запрос, интервал и какие поля ответа считать id, заголовком и текстом. Ключи хранятся отдельно и в файл не попадают, поэтому файлом можно делиться.
Петля на себяОтвет рутины — тоже сообщение. Сообщения своего бота и ответы в тредах не считаются событиями, поэтому рутина не срабатывает сама на себя.

Решения

Все пять вопросов закрыты 17.11.2026. Выбранный вариант помечен.

1. Как человек подключает свой сервисот этого зависит, насколько решение универсальное
Словами, агент собирает проверкуПодходит любому: не нужно знать API. Агент один раз тратит лимит на подключение, дальше проверки идут без модели.
Только готовые и своя командаПроще сделать. Но сервис, которого нет в готовых, подключит только тот, кто умеет писать запросы.
2. Где лежат правиламожно ли делиться с командой
~/.agentgraph/routinesЛичные, рядом с источниками и токенами. Адреса и бюджеты у каждого свои.
routines/ в репо рядом с flowsРевьюятся как код. Но два человека с одной рутиной дают двойные запуски.
3. Ответ наружукто видит, что работа взята
Спрашивать при создании рутиныПоследний шаг создания: «после моей проверки», «сразу» или «не сообщать». Первым стоит «после моей проверки»: текст ждёт на главной и уходит вместе с твоим решением.
Один вариант для всех рутинПроще, но для ревью только на чтение удобнее «сразу», а для бага — «после проверки».
4. Пропущенное расписаниеноутбук был закрыт в 9:30
Спросить один разПосле запуска строка на главной: «сводка за 9:30 не запускалась — запустить?».
Молча пропуститьПроще, но утренняя сводка тихо не придёт.
5. Первая версиячто входит в MVP
Своя команда, подключение словами, расписание, SlackКоманда и подключение словами дают любой сервис, расписание — регулярные дела, Slack — обе исходные истории. Остальные готовые источники следующими.
Сразу все видыШире, но дольше до первой работающей рутины.
