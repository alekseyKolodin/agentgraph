## Что сделано (spec §8.4, §9.2–9.3, §11; макеты PrdRead, PrdEdit, Prd)

Заглушки волны 2 `DocTab {team, project, doc}` и `DocsListTab {team, project}` заменены, props те же.

**Чтение.** Колонка 640px, кегль `--fs-read` (15px, новый токен в `tokens.css` и строка в `.interface-design/system.md`),
межстрочный 1.65. Оглавление по `##` сбоку, `position: sticky`, подсветка текущего раздела по прокрутке (слушатель
`scroll` в фазе захвата — прокручивает `main` оболочки), у текущего раздела ТЗ подпункты FR-N/NFR-N с янтарной точкой у
требований без задач, внизу «Задачи есть у N из M требований» и «FR-6 без задач». Строки требований: номер-якорь слева
(`#FR-3`), текст, на полях задачи из `useTasks` → `covers` со статусом (`бэклог`, `спринт N` для не активного, иначе
название колонки команды, `готово` — `--st-ok`); без задач — «нет задач» янтарным и «Создать задачу» (диалог с
заголовком из текста требования → `POST …/tasks { title, covers: [id] }` в бэклог → открывается `?task=`). Номера задач
(префикс команды), FR-N/NFR-N и пути `prd.md`/`architecture.md`/`design.md`/`docs/*.md` в тексте — ссылки: задача —
`?task=` поверх вкладки, требование — якорь (из архитектуры и дизайна — вкладка ТЗ с якорем), документ — его вкладка,
`docs/…` — `docs?doc=docs/…`. Шапка: файл, кто и когда, требования, время чтения (`docHeadLine`), «История»,
«Исходник», «Черновик с моделью…». Нажатие на раздел (не на ссылку и не при выделении текста) или «Править» открывает
правку.

**Правка раздела.** Один раздел на месте, остальное читается. CodeMirror 6 с `markdownLanguage` из
`@codemirror/lang-markdown` (единственная новая зависимость; импортируется язык, а не `markdown()`, — та тянет
`lang-html`, в сборке его нет; чанк `codemirror` общий с редактором flow). «Текст» — живая разметка (заголовки,
жирный, курсив, код, ссылки как при чтении, метки разметки притушены, номер `- FR-N.` моно), «Markdown» — исходник
моно. Раздел требований ТЗ в «Тексте» — строки: номер закреплён, текст в поле (без переводов строки), перетаскивание за
⋮⋮ и ⌥↑ ⌥↓ (на ⋮⋮ или в поле, фокус остаётся на строке), × удаляет (если на требование ссылаются задачи — переспрос),
Enter — к следующей строке или новое требование, «+ Требование · FR-9» — следующий номер по `doc.nextRequirement`
(учитывает `lastRequirement`) и добавленным в этой правке; задачи рядом только для чтения; текст до и после строк — своими
редакторами. Панель: Ж, К, `</>` (⌘B, ⌘I в редакторе), «#» — поиск задачи, требования или документа и вставка номера,
«С агентом…», «Текст / Markdown». Внизу «N изменений · уйдёт коммитом «export: ТЗ: Требования»», Esc/«Отмена» (с
переспросом, если есть правка), ⌘S/«Сохранить раздел» → `PUT …/docs/:name { text: «## …» + тело, section, hash, message }`.
Хэш — раздела на начало правки. 409 → «Раздел уже изменил кто-то другой» и обе версии рядом («Сейчас в репо» / «Ваша
версия»): «Сохранить мою поверх» (хэш текущего раздела) или «Взять версию из репо и править её». 404 раздела — понятная
ошибка. Правка живёт вне компонента (`edits.ts`): уход на другую вкладку проекта и обратно её не теряет; несохранённый
раздел виден в оглавлении («не сохранено») и в шапке проекта рядом со строкой синхронизации (`UnsavedLine` →
`unsavedLine()` из `lib/teamwork/sync.ts`, клик ведёт к разделу); перезагрузка страницы с несохранённым — вопрос
браузера (`beforeunload`).

**Черновики агента.** «Черновик с моделью…» (весь документ; у архитектуры и дизайна — «только этот» или «архитектура и
дизайн» → `what`) и «С агентом…» в разделе (`section`) — панель с заданием и моделью → `POST …/drafts`. Строка
черновика на вкладке документа (последний черновик, где `docs` содержит документ): идёт — «Черновик идёт · Открыть
запуск», ждёт ответа — янтарно «Ответить в запуске»; готов — «Посмотреть», «Отклонить»; не получился — «Что успел»,
«Повторить» (тот же вид, задание, раздел), «Скрыть». Пока черновик документа идёт, «Черновик с моделью…» неактивна;
список черновиков перечитывается раз в 4 с, пока что-то идёт. Рецензия — `?draft=<запуск>` на вкладке документа:
`trackChanges(base, next, notes, decisions, doc)`, у каждой правки на полях номер, причина из `notes.json`,
«Принять»/«Отклонить»/«Отменить»; новое требование помечено «новое»; разделы без правок свёрнуты строкой «… — без правок
· Показать»; в оглавлении число нерешённых; наверху задание, `решено N из M` полосой, ↑ ↓, «Принять остальные»
(конфликтные — нет), «Документ / Исходник» (построчный дифф base → next), «Отклонить черновик», «Записать принятые · N».
`dropped` → «правки в «…» отброшены», `warnings` и `error` (с «Повторить черновик») показываются. Архитектура с двумя
документами: на каждой вкладке свой документ черновика и `notes` по полю `doc`; принятие с `doc`.

Принятие: документ не менялся — `applyDecisions(base, next, принятые)` с `base: baseHash`; менялся (`moved`) — принятые
правки накладываются на текущую версию (`merge3`, ниже) с `base: currentHash`. Правки, чей старый текст поменяли после
старта (`markConflicts`), помечены и принимаются только кнопкой «Принять вручную». 409 `conflict` при записи — черновик
перечитывается, сообщение «Документ успели изменить…» и дифф «что изменили в репо после старта черновика»; запись ещё
раз идёт с новым `currentHash`. 409 `busy` — «Черновик ещё идёт». Решения и записанные правки браузер помнит по запуску
(`localStorage` `agentgraph.teamwork.draft.<run>.<doc>`: `{ d: решения, w: записанные, x?: закрыт }`): частичная
запись оставляет нерешённые, к ним можно вернуться; свою прошлую запись рецензия не считает «чужими изменениями». Всё
решено и записано или «Отклонить черновик» — строка черновика больше не показывается (запуск остаётся в списке).

**Архитектура и дизайн** — тот же вид без блоков требований, ссылки на FR-N ведут в ТЗ. **`docs/`** — список файлов
слева (на узком экране — строкой над документом), выбранный (`?doc=docs/<файл>`) — тот же вид с правкой по разделам,
«Историей» и «Исходником», без черновиков; «+ Документ» заводит `docs/<имя>.md` одним коммитом.

**Пустые состояния (spec §11).** ТЗ, архитектура или дизайн только из заголовков заготовки — «ТЗ пока пустое» с
«Черновик с моделью…» и «Писать самому»; файла нет в репо — «Файла … нет» с «Черновик с моделью…» и «Создать пустой»;
формат репо новее (`sync.state === 'readonly'`) — без правки и черновиков; файл не читается — строка ошибки.

Чистая логика — `web/src/lib/teamwork/doc-view.ts` (+ `doc-view.test.ts`, 15 тестов): `readChunks` (куски раздела для
чтения), `isDocEmpty`, `isReqSection`, `reqKindFor`, `lastIssued`, `taskWhere`, `refTarget`, `draftRunning`,
`draftFailed`, `latestDraftFor`, `draftLine`, `merge3`, `draftResult`, `wrapMark`, `rowChanges`, `sectionName`, якоря.

`merge3(base, ours, theirs)` — по блокам `parseBlocks`: каждый кусок наших правок (base → ours) ложится на theirs —
старые блоки на месте → заменяются ровно они; вставка — сразу за общим соседом (уже вставленная та же — не повторяется);
старые блоки у них поменяли → конфликт, наш кусок заменяет всё между общими соседями (такие правки человек принял
вручную). Первая версия делала классический diff3 по общим якорям и теряла чужую правку в соседнем блоке — поймано в
браузере, есть тест.

## Не проверено

- Настоящий запуск `teamwork-prd`/`teamwork-architecture` с Agent SDK (деньги): старт — только на подменённом `fetch`,
  живая строка «идёт» — тоже; рецензия — на запусках, записанных руками.
- «Повторить» у упавшего черновика не нажимал (стартует настоящий запуск); строка «Черновик не получился · Что успел ·
  Повторить · Скрыть» и рецензия с `error` («Черновик не читается», «Повторить черновик») проверены на поддельном
  упавшем запуске без снимка flow.
- Вид «только чтение» (формат новее) — на подменённом кэше (`sync.state: 'readonly'` через `__agentgraphQuery`): нет
  «Править», «Создать задачу» и черновиков, «История» есть; от сервера с настоящим репо нового формата — нет.
- Перетаскивание мышью (HTML5 drag-and-drop) строк требований: проверена клавиатура ⌥↑ ⌥↓, мышью в панели браузера —
  нет (эмуляция масштаба сбивает координаты).
- Узкий экран ≤ 800px контейнера (без оглавления, поля под текстом) смотрел только на 1024 окна (контейнер ~780), на
  телефонной ширине — нет.
- Английский интерфейс посмотрел только на ТЗ (шапка, оглавление, редактор раздела) — рецензию черновика и диалоги на
  английском не открывал.
