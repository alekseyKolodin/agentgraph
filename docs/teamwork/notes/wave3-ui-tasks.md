## Решения, которые стоит знать

- **Форма «В работу» своя, короткая.** Форма вкладки «Запуск» (`screens/flow/RunForm.tsx`) живёт на экране flow и открывает только
  flow из `flows/` этого компьютера (`/flow/<имя>` + `location.state.intake`, как «Запустить…» на главной); flow команды лежат в
  репо команды, и `teamFlow`, `teamwork`, `addDirs` она не передаёт. Поэтому в диалоге — только то, что нужно задаче, а тело
  собирается по тем же полям, что `runBody` формы запуска, плюс `teamFlow`/`flow`, `teamwork`, `worktree`, `addDirs`, `source`
  (`workRunBody`, тест). Переиспользованы `startRun`, `SpacePicker`, `modelOptions`, `withWorktreeNote`. Смена flow команды —
  заново `GET …/intake?flow=`, свой flow — `myFlowInput(шаблон flow, «PAY-3 — заголовок», ветка, intake.context)`.
- **Очередь записей задачи** (`useTaskOps`): одна на задачу для всех экранов проекта (модуль, а не компонент: перенос с доски и
  галочка в панели идут друг за другом). Правка сразу в кэше, запрос — по последней версии с сервера (не по кэшу с мгновенными
  правками, иначе «+ критерий» ложился дважды — пойман живьём), `base` — из ответа предыдущего запроса, поверх ответа снова ложатся
  ещё не отправленные правки. Ошибка: версия с сервера остаётся прежней (409 — `data.current`), упавшая правка снимается, следующие
  строятся без неё. Перечитанный список задач (событие `team`, опрос) не затирает ждущие правки — подписка на кэш запросов кладёт их
  сверху. После записи перечитываются только команда и проект (точные ключи), не список задач.
- **Нечитаемые задачи** (битый файл, `rank` пустой) стоят в конце списка и колонки, без перетаскивания и «Переместить…», соседями
  при переносе не считаются (сервер такого соседа не принимает); удалить их можно.
- **Групповой перенос** («В следующий спринт», «В бэклог») виден сразу, а запросы идут по одному (`move(id, drop, after)`): сосед
  следующей задачи — предыдущая. Мгновенный ранг — как поставит сервер (`dropRank`: без соседей ранг не меняется), карточки не прыгают.
- **Перетаскивание**: нативный HTML5 DnD без зависимостей. С включённым фильтром доски оно выключено (позиция считалась бы по
  видимым карточкам) — меню и ⌥-стрелки работают; под доской подпись об этом. Фокус после переноса возвращается на карточку
  (`useKeepFocus`, `[data-task]`).
- **Кнопки карточки доски** («В работу ▸», ⋯) видны при наведении и фокусе (в табе остаются), у ждущей и упавшей карточки —
  всегда («Ответить», «Открыть запуск»). На устройствах без hover — всегда.
- **Разобранные черновики разбивки** (принят или «Отклонить») запоминаются в браузере
  (`agentgraph.teamwork.splitDone.<team>.<project>`, последние 20), чтобы предложение не всплывало снова; сам черновик остаётся в
  запуске. Проверка связей на клиенте идёт по отмеченным задачам: снятая галочка у предшественника — ошибка «неизвестная задача»
  у зависимых, «Добавить» недоступна, как ответит и сервер. Ответ 400 `dependencies` подсвечивает `report.errors` у задач.
- В тексте разбора ключи предложения показываются как на графе: «1 → 2 → 6», «цикл: 3 → 7 → 3» (`labelKeys`; номера `PAY-3` не трогаются).
  Связь на неотмеченную задачу предложения — «ждёт задачу 3, а она не отмечена» вместо серверного «неизвестная задача».
- Узел графа на 6 px выше макета (82 вместо 76): две строки заголовка и строка требований иначе обрезались.
- Ключи localStorage: `agentgraph.teamwork.board.<team>.<project>` (фильтр доски, через `LS` с try/catch),
  `agentgraph.teamwork.splitView`, `agentgraph.teamwork.splitDone.<team>.<project>`.

## Ревью

Независимое ревью (`code-reviewer`, только чтение): блокеров нет, 5 важных и 8 мелких замечаний — все исправлены вторым коммитом:
очередь записей при ошибке и при перечитке списка (выше), нечитаемые задачи как соседи переноса, порядок группового переноса, тело
задачи без раздела критериев (галочки дублировались при правке описания и терялись при «+ критерий»), правка галочки больше не
трогает остальной текст (пустые строки в коде, отступ первой строки — `rebuild`, ограды по `fencedLines` как у сервера), бросок в
зазор между карточками, «В работу»: отказ intake другого flow возвращает прежний выбор, «Мои flow», пришедшие позже, дают flow по
умолчанию, фокус после закрытия — на «В работу ▸»; линия связи на графе снимается по `pointercancel` и отпущенной кнопке; ⌥-стрелки
в открытом меню не двигают карточку; «Убрать из спринта в бэклог» ставит задачу в начало бэклога и переводит фокус на соседнюю
карточку (или заголовок колонки). Живьём перепроверены: битый файл в бэклоге и «В начало» рядом с ним, групповой перенос (порядок в
интерфейсе в каждый момент совпадал с сервером), «+ критерий» с подменённым 500 и «×» за ним при принудительной перечитке (ровно
одно удаление, упавший критерий не записан), бросок в зазор, отказ intake и возврат фокуса.

## Не проверено

  (те же обработчики React). Связь в графе — настоящей мышью (там pointer events).

- 409 `conflict` при параллельной правке задачи двумя клонами, режим `readonly`, тач-устройства. Английский интерфейс смотрел
  только на доске и панели задачи (остальные ключи проверены скриптом: у всех `t()` новых файлов есть перевод).
- `scripts/check-sdk-hooks.mts` не запускался (guard и права сессий не трогались).

## Замечания соседям

- core: номер удалённой задачи переиспользуется, если она была последней (удалил PAY-8 — следующая новая стала PAY-8). По §5.7 это
  «максимум плюс один», но `local.json → work` по старому номеру и упоминания в `result` закрытых спринтов и в тексте задач
  переезжают на новую задачу. Стоит помнить выданный максимум, как `lastRequirement` у требований.
- core: `POST …/tasks` не читает `after`/`before` из `NewTask` (в типе `web/src/api/teamwork.ts` они есть) — новая задача всегда в
  конце своего списка. Для бэклога это совпадает с макетом, для «+ Задача» на доске тоже, но поле в типе вводит в заблуждение.
- ui-logic: в `layoutGraph`, когда предложенная задача в цикле, существующие предшественники пропадают с графа (у них нет волны).
- ui-logic: `startNote` с одним внешним предшественником пишет «Сейчас её делает …/Исполнителя у неё пока нет» и тогда, когда есть
  ещё и предшественник из предложения — фраза относится к внешнему, читается двусмысленно.
- finish: «Мои задачи» на главной могут брать `ToWorkButton` и `useTaskHref`-подобную ссылку `/teamwork/<t>/<p>/board?task=ID`.
