Ветка `claude/tw-fix-web-93303a` от `ddc346b`. Пункты — из раздела «W» `docs/teamwork/notes/final-review.md`.
`npm run typecheck && npm test && npm run build:web` зелёные (1294 теста, было 1280). `src/` не тронут.

## Общие решения

- **Ошибка перечитки поверх данных** (`lib/teamwork/form.ts` → `failView`, `parts.tsx` → `StaleLine`). Без данных — экран
  ошибки, как раньше; с данными (упал опрос, событие `team`, перезапуск сервера) — строка «Не обновилось: … — показано
  последнее загруженное» над содержимым. Следующая удачная перечитка её снимает.
- **Несохранённый ввод** — хранилище по ключу вне компонентов, как `docs/edits.ts`: само хранилище — `lib/teamwork/unsaved.ts`
  (с тестом), хук `useUnsaved` на `useSyncExternalStore` и вопрос браузера при перезагрузке (`guardUnsaved`) —
  `screens/teamwork/unsaved.ts`. Почему не `useMemoryState`: его запись после размонтирования теряется (`setValue` с функцией
  не выполняется у снятого компонента), и отправленный комментарий или сохранённое описание всплыли бы снова при возврате к
  задаче. Здесь запись идёт по ключу всегда. Название — «несохранённое»: «черновик» в Teamwork — черновик агента.
  `useMemoryState` остался там, где был (открытость формы нового проекта, выбранный flow «Процесса»).
  Где закрытие окна или уход теряют ввод без хранилища — `askConfirm` («Бросить правку …? Изменения пропадут.», как у раздела
  документа).
- **Фокус окон** — `screens/teamwork/focus.ts`: `useReturnFocus(ref)` по образцу `ToWork.tsx:113-121` (запомнить элемент на
  первой отрисовке, вернуть фокус после размонтирования, только если окна нет в DOM и фокус никто не поставил сам) и
  `trapTab` — Tab/Shift+Tab по кругу в панели задачи (`aria-modal` без `<dialog>`); шаг ловушки — `trapStep` в
  `lib/teamwork/focus.ts` с тестом. Нативный `showModal()` держит фокус сам, ему нужен только возврат.
- **Формы поверх перечитываемых данных** — `rebaseForm` и `changedFields` в `lib/teamwork/form.ts`: поле, которое поменяли в
  данных и не трогали в форме, берёт свежее значение (по одному, сравнение без пробелов по краям); запись — только поля,
  изменённые относительно базы формы.

## Ревью

Два прохода `code-reviewer` по диффу (только чтение; typecheck, тесты, сборка у него зелёные).

Первый — «после правок», high нет:
- **M1** — Esc сразу после ⌘Enter бросал описание до ответа сервера (оптимистичный кэш совпадал с текстом, вопроса не было), при 409
  текст пропадал; в панели, открытой заново во время запроса, «Отмена» закрывала без вопроса и можно было отправить второй раз. →
  флаг сохранения в `unsaved.ts`, во время запроса Esc и «Отмена» ничего не бросают, грязность — относительно описания на момент
  «Править».
- **M2** — правка описания, пережившая закрытие панели, молча перетирала правку коллеги (`base` берётся свежий, 409 нет). → правка
  помнит исходное описание; если его поменяли — предупреждение с версией команды и вопрос «Заменить» перед сохранением.
