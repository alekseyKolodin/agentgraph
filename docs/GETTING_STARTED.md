# agentgraph: как это работает и как этим пользоваться

Короткое руководство для тех, кто видит проект впервые. Полный справочник (все поля `flow.yaml`, все кнопки UI, API) лежит в [REFERENCE.md](REFERENCE.md), обзор с демо — в [README](../README.md); здесь только то, что нужно, чтобы начать.

## Что это

agentgraph запускает Claude Code не одной сессией, а **цепочкой этапов в цикле**, пока не выполнится условие.

```
задача ──► этап 1 ──► этап 2 ──► … ──► условие ──► готово
              ▲                            │
              └──── замечания условия ─────┘   (следующая итерация)
```

Несколько слов, которые встретятся дальше:

- **Flow** — YAML-файл в `flows/`: из каких блоков и этапов он состоит, что делает каждый этап (промпт), какие у него инструменты и когда результат считается готовым.
- **Этап** (в YAML — поле `phases`) — свежая сессия Claude Code со своим промптом. В промпт подставляются задача (`{{input}}`) и вывод предыдущего этапа (`{{prev}}`).
- **Группа** (в YAML — поле `group` у этапа) — соседние этапы одного блока, которые идут одновременно. Все они видят один `{{prev}}` — вывод до группы, а следующий этап получает склейку их выводов. Подходит для независимых ревью и исследований.
- **Блок** — набор этапов: либо цикл до условия, либо один проход. Flow может состоять из нескольких блоков подряд. Например: «писать ТЗ, пока судья не примет» → «разбить на задачи за один проход» → «реализовывать, пока тесты не зелёные».
- **Условие** проверяется после прохода всех этапов блока. Типы: **команда** (shell-команда вернула 0, например `npm test`), **судья** (сессия Claude оценивает результат по рубрике) и **маркер** (в выводе этапа есть заданная строка). Если условие не выполнено, начинается новая итерация.
- **Замечания** — что сообщило условие: вывод упавшей команды или замечания судьи. Они попадают в промпты следующей итерации как `{{feedback}}`.
- **Артефакт** (в YAML — поле `artifacts`) — именованный файл запуска: план, чек-лист, решения. Живёт весь запуск, переживает итерации и блоки и переносится при продолжении. Этап получает его через `reads`, `writes` или `{{artifacts.KEY}}` и пишет только в свои `writes`. Ты можешь поправить его в UI между шагами, и следующий этап увидит правку. В отличие от `{{prev}}`, который живёт до следующего этапа, у артефакта одна текущая копия.
- **Задача** — что нужно сделать. Её текст подставляется в промпты как `{{input}}`.
- **Тег задачи** — запись о фиче, которая переходит между запусками: реализация, фикс багов, правки по ревью, конфликты. Задача — что сделать в этом запуске, тег — что за фича и где она сейчас. В теге — саммари (его после успешного запуска переписывает модель), твои заметки, пути и вложения; всё это подставляется в начало задачи. Тегов на запуск может быть несколько. Тег выбирают или вписывают в форме запуска, или новый тег заводит ИИ галочкой «Завести тег задачи автоматически». Лежит в `~/.agentgraph/tags/<slug>/`, правится на странице «Теги».
- **Тег области знаний** — что должны знать этапы блока: фронтенд, бэкенд, QA. Заметки (инструкции), пути и вложения; саммари нет. Вешается на блок полем `knowledge: [qa]` в flow.yaml или на весь запуск чипом в форме; этапы блока получают раздел «Область знаний» в конец промпта и пути тега на чтение.
- **Запуск** — одно исполнение flow. Всё, что происходило, сохраняется в `runs/<дата>-<flow>/`.
- **Разовый запуск** — запуск flow, который не сохраняется в `flows/`: flow генерируется под задачу, правится черновиком и сразу запускается. Его единственная копия — снимок `runs/<id>/flow.yaml`, в `run.json` стоит `adhoc: true`. Понравился — «Сохранить как flow».
- **Директория проекта** — папка, где агенты читают и правят файлы: твой целевой проект, а не папка agentgraph.

Flow можно написать руками, собрать в конструкторе UI или сгенерировать из описания задачи: генератор (тоже Claude) сам предложит этапы, промпты и условие.

## Что нужно заранее

| | |
|---|---|
| **Node.js 20+** | `node -v` |
| **Claude Code с авторизацией** | agentgraph работает через `@anthropic-ai/claude-agent-sdk` и использует ту же авторизацию, что и `claude` в терминале: вход по подписке (`claude`, затем `/login`) или переменная `ANTHROPIC_API_KEY`. Если `claude` у тебя в терминале работает, agentgraph тоже заработает. |
| macOS или Linux | на Windows не проверялось |
| `terminal-notifier` (по желанию, macOS) | `brew install terminal-notifier`: клик по системному уведомлению открывает нужный запуск |

## Установка

```bash
cd agentgraph          # распакованный архив или клон репозитория
npm install
```

`npm install` скачивает в том числе бинарник Claude Code под твою платформу. Поэтому `node_modules` нельзя копировать с чужой машины: ставь зависимости у себя.

Проверить, что всё на месте:

```bash
npm run typecheck && npm test
```

## Запуск

Основной способ — веб-интерфейс:

```bash
npm run ui
```

Открой http://127.0.0.1:4747. Полезные опции (через `--`):

```bash
npm run ui -- --cwd ~/code/my-repo   # директория проекта по умолчанию в форме запуска
npm run ui -- --port 4848            # другой порт
npm run ui -- --no-notify            # без системных уведомлений
```

Интерфейс — React-приложение из `web/`. `npm run ui` сам собирает его в `dist/web` перед стартом сервера, если сборки нет или `web/` изменился (первый раз — несколько секунд). Собрать вручную: `npm run build:web`. Старые ссылки на запуски и flow (`/#run/<id>`, `/#flow/<имя>`, `/next/…`) открывают те же экраны.

Остановить сервер: `Ctrl+C`. Запуски, которые в этот момент шли, прервутся, а в списке будут видны как «оборвался». Такой запуск можно продолжить с места остановки.

### Десктопное приложение (macOS)

Тот же сервер и тот же UI в отдельном окне, без терминала и вкладки браузера. Обёртка на Electron: главный процесс (`src/desktop/main.ts`) вызывает `startServer()` из `src/server.ts` на свободном порту `127.0.0.1` и открывает окно на `http://localhost:<порт>/` — именно по http, а не с `file://`, иначе `server-guard.ts` отклонит запросы. Electron, а не Tauri: Agent SDK работает только в Node, а Electron несёт Node внутри.

```bash
npm run desktop:dev     # собрать UI (если устарел) и сервер, открыть окно; данные — из корня проекта, как у npm run ui
npm run desktop:build   # собрать release/desktop/agentgraph-<версия>-<arch>.dmg и .zip (и сам .app в release/desktop/mac-<arch>/)
```

Бинарник Electron (~100 МБ) скачивается при первом `desktop:dev` или `desktop:build`, а не при `npm install`: тем, кто пользуется только `npm run ui` и CLI, он не нужен.

Что важно знать:

- **Где данные.** В `desktop:dev` — корень проекта. Собранному приложению нужна папка с `flows/` и `runs/` снаружи: `AGENTGRAPH_HOME` (в том числе из `~/.zshrc` — приложение подхватывает окружение login-shell), иначе при первом запуске оно спросит папку (например, checkout agentgraph) и запомнит её; отмена — пустая папка внутри приложения. Сменить: меню «Файл → Папка данных…». Запомненное (папка, порт) — в `~/Library/Application Support/agentgraph/desktop.json`.
- **Доступ к «Документам».** Если папка данных или проекта в `~/Documents`, `~/Desktop` или `~/Downloads`, macOS при первом обращении спросит разрешение. Пока не ответишь, окно не отвечает: системный диалог может оказаться позади окна приложения.
- **Порт** свой, не 4747: приложение и `npm run ui` могут работать одновременно. Но над одними `runs/` запуск, начатый в одном, второй покажет как «идёт в другом процессе», управлять им можно только оттуда. Скиллу `/agentgraph` адрес приложения передаётся через `AGENTGRAPH_URL` (порт — в `desktop.json`).
- **Закрыть окно** — запуски идут дальше, клик по иконке в Dock открывает окно снова. **Выйти (Cmd+Q)** — идущие запуски останавливаются, как кнопкой «Стоп» (агенты гасятся, запуск получает итог «прервано», его можно продолжить), потом приложение закрывается.
- **Claude Code внутри.** Agent SDK запускает CLI Claude Code из пакета под платформу; в приложении он лежит в `app.asar.unpacked` (изнутри asar процесс не запустить), путь SDK получает через `AGENTGRAPH_CLAUDE_EXECUTABLE`. Авторизация общая с `claude` в терминале.
- **Упаковка — electron-builder** (`electron-builder.yml`), а не Electron Forge: сборка у нас уже своя (`tsc` для сервера, Vite для UI), и electron-builder просто упаковывает готовый `dist/` с `dependencies` из `package.json`, а распаковка бинарника SDK из asar и цели dmg/zip задаются парой строк конфига. Forge хочет вести сборку сам через свои плагины Vite/webpack.
- **Ограничения.** Приложение не подписано: на другом Mac его откроют через правый клик → «Открыть» (или `xattr -dr com.apple.quarantine agentgraph.app`). Сборка — только под архитектуру машины, на которой собирали: бинарник Claude Code в `node_modules` ставится под неё, universal-сборки нет.

## Первый прогон (стоит центы)

1. В UI слева выбери flow **example-blocks** (папка `example`). Flow открывается сразу на вкладке **Запуск**.
2. Загляни в соседнюю вкладку **Конструктор**: три блока, у каждого этапа виден промпт, инструменты и что этап передаёт дальше.
3. Вернись на **Запуск** → **Запустить**. Задача уже заполнена, инструментов у этапов нет, поэтому файлы никто не тронет.
4. На странице запуска видно, как этапы идут по итерациям, что ответил судья и сколько это стоило. Кнопки «промпт / транскрипт / вывод» у каждого этапа показывают, что именно ушло агенту и что он вернул.

Ещё четыре примера в `flows/example/`:

- **example-ask** — агент задаёт вопрос пользователю (инструмент `AskUserQuestion`). Вопрос всплывает в UI, отвечаешь там же.
- **example-pause** — агент сам ставит запуск на паузу, когда без человека не обойтись (`loop.pause_marker`).
- **example-parallel** — три этапа идут одновременно (параллельная группа `group`), четвёртый сводит их выводы. На странице запуска видно несколько этапов «выполняется» сразу.
- **example-artifacts** — артефакты запуска: файл идей переживает итерации, этап `brainstorm` дописывает в него идеи, `pick` выбирает лучшую. Попробуй поправить курс: нажми «Пауза», пока идёт `pick` первой итерации, открой «Идеи» в панели «Артефакты», допиши строку («дальше только русские названия из одного слова») и нажми «Сохранить и возобновить». Вторая итерация получит правку. Модель `claude-haiku-5-5`, около $1.4 за прогон.

## Обычная работа

### Создать flow

- **«Новый flow» → сгенерировать**: опиши задачу словами («почини падающие тесты, сами тесты не трогать»), генератор предложит flow. Перед запуском проверь промпты, инструменты и условие.
- **«Новый flow» → собрать руками**: пустая заготовка, этапы добавляются в конструкторе.
- **«Новый flow» → разовый запуск (не сохранять flow)**: как «сгенерировать», но flow не сохраняется. Черновик открывается в конструкторе с пометкой «разовый»: правь руками, «Правкой с ИИ» или в YAML, кнопка «Применить» только проверяет правку. Дальше вкладка **Запуск** → «Запустить»: запуск пойдёт по тому, что сейчас в конструкторе, а в `flows/` ничего не появится. Черновик живёт только в этой вкладке браузера, уход с него спрашивает подтверждение. На странице такого запуска вместо «К flow» — «Сохранить как flow» (имя и папка; занятое имя не перезаписывается).
- **Правка с ИИ** (над графом в конструкторе): опиши, что поменять («добавь этап ревью после реализации»). Правка ложится в конструктор несохранённой: смотришь, что изменилось, и жмёшь «Сохранить» (кнопка внизу появляется при несохранённых правках) или «Отменить правку».
- Вкладка **YAML** — для тонкой правки текстом.

Flow сохраняются в `flows/<имя>.yaml` или `flows/<папка>/<имя>.yaml`. Это обычные файлы: их можно класть в git и пересылать коллегам.

### Запустить

Вкладка **Запуск**:

- **Теги задачи** — над задачей: выбери фичу из списка или впиши новый слаг (`loyalty-card`) и нажми Enter; тегов может быть несколько, крестик на чипе убирает тег. Блок каждого тега (саммари, заметки, пути, вложения) появится в начале задачи, фичу заново описывать не нужно — пиши только, что сделать сейчас. Галочка **Обновить саммари тегов после запуска** включена по умолчанию: после запуска со статусом «готово» саммари каждого тега перепишется. В карточке «Итог» по каждому тегу будет строка «Саммари тега обновлено» с кнопкой «саммари» или причина, почему не обновлено. Сами теги — заголовок, саммари, заметки, пути, вложения — правятся на странице **Теги** в боковой панели. Подробнее — в справочнике, раздел [«Теги»](REFERENCE.md#теги-задачи-и-области-знаний).
- **Задача** — что нужно сделать, уходит в `{{input}}`.
- **Директория проекта** — где агенты читают и правят файлы, то есть твой целевой проект, **а не** папка agentgraph. Путь можно не набирать: кнопка **Выбрать…** открывает окно выбора папки в Finder (только macOS). Та же кнопка есть в форме нового flow, при добавлении проекта в «Подключениях», у «Дополнительных директорий» этапа в конструкторе и у «Дополнительных директорий» в форме запуска (в обоих полях выбранная папка дописывается новой строкой).
- **Вложения** — скриншоты, PDF, логи и другие текстовые файлы к задаче: «Добавить файлы…», перетаскивание на форму или вставка скриншота прямо в поле задачи. До 10 файлов, до 10 МБ каждый, до 25 МБ вместе; `.docx` не принимается. Пути к ним получает каждый этап, но открывает их агент инструментом Read, поэтому этапы без Read вложений не увидят. Форма покажет, какие это этапы.
- **Дополнительные директории** — по пути на строку: куда, кроме директории проекта, могут ходить все этапы этого запуска (например, соседний репозиторий с правилами). Работают как `add_dirs` этапа, но на весь запуск.
- **Недавние директории** — чипы под директорией проекта и под дополнительными директориями: последние пути запусков и проекты из «Подключений». Клик подставляет путь, искать заново не нужно; «×» на чипе убирает путь из списка, пока с ним не будет нового запуска.
- **Лимит итераций**, **лимит стоимости** (USD) и **модель** — по желанию.

### Следить и вмешиваться

- **Главная** (первый пункт слева, на нём счётчик вопросов; логотип тоже ведёт сюда) показывает все идущие запуски и вопросы агентов из всех запусков сразу. Отвечать можно прямо с главной.
- **Лимиты** (в шапке главной): сколько израсходовано из 5-часового и недельного окна подписки Claude и когда окно сбросится — те же цифры, что в `/usage` Claude Code. Обновляются раз в минуту, клик — обновить сразу. С ключом API (без подписки) блока нет.
- **События** (окно справа на главной): лента вопросов агентов, пауз по их просьбе и концов запусков — всё, о чём приходят уведомления, включая пропущенное, пока UI был закрыт. Новое подсвечено до «Отметить прочитанным», клик открывает запуск. Видны первые 20 событий, остальные открывает «Ещё N».
- **Фильтр по статусу** над списком запусков слева: показать, например, только упавшие или только ждущие ответа.
- **Имя запуска**: через несколько секунд после старта модель даёт запуску короткое имя по задаче. Оно стоит заголовком в списке, на странице запуска и на главной, а имя flow — мелко под ним. У старых запусков заголовок — flow.
- **Поиск** в сайдбаре: «Найти flow…» ищет по имени, папке и описанию flow, «Найти запуск…» — по имени, flow, задаче, тегам, папке проекта и id запуска. Работает вместе с фильтром по статусу, Esc очищает поле.
- **Чат запуска** вверху страницы запуска (по умолчанию свёрнут, раскрывается кликом по заголовку): спроси агента, что происходит и почему, или попроси поставить на паузу, возобновить, поднять лимит итераций, ответить на вопрос этапа, продолжить с места остановки. «Очистить контекст» или `/clear` начинают разговор заново.
- **Вопросы агента и причина паузы** показываются отформатированным markdown, заголовок вопроса — плашкой; у отвеченного вопроса ответ стоит под вопросом.
- **Промпт идущего этапа**: на карточке ⏳ кнопки «промпт» и «транскрипт» появляются сразу при старте этапа, у проверки судьёй — «промпт судьи». Промпт и вывод открываются отформатированным markdown, «как текст» в шапке окна показывает исходник. Текст больше 300 000 символов или со строкой длиннее 10 000 символов показывается моноширинно без разметки. Транскрипт читается заново при каждом открытии.
- **Модель и effort этапа**: на карточке каждого этапа (идущего и прошлых) чип «модель · effort». Модель фактическая, из `system/init`: у идущего этапа без заданной модели появляется через секунду после старта. Effort заданный (этап → `defaults`): SDK фактический не отдаёт, без значения чипа effort нет. Данные лежат в `run.json` (`phases[].model`, `phases[].effort`), у старых запусков чипа нет.
- **Контекст этапа**: рядом с моделью чип `ctx 172k / 1M · 17%` — пик контекста этапа, окно модели и процент (от 70% жёлтый, от 90% красный); у идущего этапа растёт по ходу сессии. Данные — `phases[].tokens` в `run.json` (`contextPeak`, `contextWindow`); у старых запусков без окна только `ctx 90k`, без `tokens` чипа нет.
- **Схема запуска** над блоками этапов: граф flow, на котором видно, на каком этапе и итерации сейчас запуск, что пройдено и сколько это стоило; клик по узлу ведёт к карточке этапа или открывает артефакт; в бейдже узла этапа — процент занятости контекстного окна.
- **Свернуть итерации**: на странице запуска блоки и итерации сворачиваются по клику на заголовок, а кнопка «Свернуть все» / «Развернуть все» делает это разом; по умолчанию открыта только текущая. Живой лог открыт только у идущего запуска.
- **Пауза**: текущий этап доработает, следующий не начнётся до «Возобновить». Это лучшее время поправить артефакты: пока стоит пауза, их никто не пишет.
- **Артефакты** (панель на странице запуска, только у flow с `artifacts`): свёрнутая строка говорит, сколько артефактов, какой изменён последним и кем и не пишет ли их сейчас этап. Раскрой её и кликни по названию: откроется окно с текстом, превью markdown и версиями. «Править» → «Сохранить» (или «Сохранить и возобновить» на паузе); правку получит каждый шаг, который начнётся после сохранения, с пометкой «последнюю правку сделал пользователь». Пока идёт этап, который пишет этот артефакт, правка заблокирована с причиной. Если закрыть окно, не сохранив, текст останется черновиком («не сохранено»), а «Возобновить» спросит, сохранить ли его. Предупреждения (этап записал не туда, в папке появился посторонний файл) видны значком ⚠ на итерации и на артефакте. У markdown-артефакта с чек-листом (`- [ ]`, `- [x]`) в строке и в шапке окна стоит бейдж «открыто N из M»: он обновляется по ходу запуска и после сохранения правки.
- **Ответ на паузу**: если агент попросил решения, а во flow есть артефакт решений (`decisions: true`), под карточкой паузы есть поле «Ответ». Напиши ответ и нажми «Возобновить с ответом» (та же кнопка в шапке): ответ допишется в артефакт решений вместе с вопросами агента, и запуск пойдёт дальше. С главной кнопка «Ответить на странице запуска» ведёт туда же. Если артефакта решений нет, карточка предложит «Открыть артефакты» или, у flow без артефактов, записать решение туда, куда просит агент.
- **Остановить запуск**: прерывает текущую сессию сразу.
- **Продолжить с места остановки**: запуск из нескольких блоков, который упёрся в лимит, упал или был остановлен, можно продолжить. Уже принятые блоки повторно не выполняются, артефакты переезжают в новый запуск вместе с твоими правками после остановки. Flow из одного блока так не продолжается: его запускают заново.
- **Включить уведомления** (кнопка на главной, пока браузер не спросил разрешение): уведомления браузера о вопросах и конце запуска. Если разрешение запрещено, на главной будет «Уведомления выключены». Если UI закрыт, системное уведомление пришлёт сервер.

### Посмотреть, что уходит в контекст

- Открой **Контекст** слева и выбери директорию проекта: появятся CLAUDE.md и правила с токенами, скиллы, сабагенты, MCP и общий итог по токенам.
- Выбери flow и этап, чтобы увидеть контекст именно этого этапа: его модель, инструменты, свой системный промпт (`system`) и CLAUDE.md из `add_dirs`. Если директории из `add_dirs` нет, будет предупреждение.
- «Открыть» у CLAUDE.md или правила открывает редактор с превью; «Сохранить» пишет файл на диск. Скиллы, плагины и managed-политики только смотрятся.
- Листинг кэшируется на минуту: после правок файлов снаружи нажми «Обновить».

### Запуск из задачи Jira, MR или ветки

На главной, в разделе **Задачи и код**, видны задачи Jira, а также открытые MR и локальные ветки твоих проектов. Видны первые 5 строк каждого списка, остальные открывает «Ещё N». У каждой строки есть кнопка **Запустить…**: выбираешь flow, и открывается его вкладка «Запуск» с готовой задачей. Сам запуск не стартует: задачу можно проверить и поправить.

- **Что попадает в задачу**: ключ и ссылка, тип и статус, родитель, сабтаски, связи и описание (для MR — ветки и описание MR). Описание обёрнуто в теги `source-data` с пометкой, что это данные, а не инструкции для агента. Если у flow в `input` есть анкета с плейсхолдерами `<...>`, она встаёт сверху, а строки `Тикет: <...>` и `Ветка: <...>` в ней заполняются сами.
- **Jira** подключается кнопкой **Подключения**: адрес вида `https://company.atlassian.net`, email и [API-токен](https://id.atlassian.com/manage-profile/security/api-tokens). Токен проверяется до сохранения, ложится в `~/.agentgraph/jira-token` с правами 600 и обратно в браузер не отдаётся. Пресеты: «Мой спринт», «Все мои» (незакрытые) и «Своя JQL»; последняя JQL запоминается.
- **Проекты** подхватываются сами из директорий проекта прошлых запусков (только существующие git-репозитории). В «Подключениях» проект можно добавить руками, переименовать или убрать: убранный автоподхват больше не вернёт. MR загружаются через [`glab`](https://gitlab.com/gitlab-org/cli), его нужно поставить и авторизовать (`glab auth login`); «Мои» берёт твой логин из `glab`.
- **Отдельный git worktree**: в форме запуска выбери проект и ветку и нажми **Подготовить worktree**. Он ляжет в `~/.agentgraph/worktrees/<репо>/<ветка>`, директория проекта подставится сама, а в конец задачи допишется видимая заметка про worktree. Как выбирается ветка: локальная берётся как есть; если она есть только в origin, создаётся отслеживающая; если её нет нигде, создаётся новая от базовой ветки проекта (по умолчанию `origin/HEAD`); без ветки получится detached HEAD. Ветку, уже выгруженную в основном checkout, взять нельзя: сначала переключи его. Неотслеживаемые файлы вроде `local.properties` укажи в настройках проекта, они скопируются в новый worktree. Сами worktree agentgraph не удаляет: `git worktree remove <путь>`.
- **Связанные запуски**: запуск помнит, из какой задачи, MR или ветки он начат и в каком worktree шёл, в том числе после «Продолжить с места остановки». Под строкой на главной видны его чипы со статусом.

Над этим разделом стоит секция **Мои MR: нужно внимание**. В неё попадают твои открытые MR из проектов «Подключений», которым что-то нужно от тебя:
- упал последний пайплайн (бейдж «CI упал» ведёт на пайплайн);
- обсуждения ждут ответа: обсуждение не разрешено, и последнее несистемное сообщение в нём не твоё, боты тоже считаются;
- есть конфликты с целевой веткой.

**Запустить…** собирает вход так же, как в «Задачах и коде», и добавляет строку с причинами. В фоне haiku подбирает каждому MR подходящий flow из твоих. Если такой нашёлся, в строке появляется чип «→ <flow>»: клик открывает «Запуск» этого flow с готовым входом. Если подходящего flow нет, подсказки нет, и это нормально. Сам запуск и здесь не стартует. Список обновляется кнопкой ↻.

### Где результат

Агенты работают прямо в директории проекта: правки кода, новые файлы, коммиты появляются там. Что получилось, видно сразу: у завершённого запуска наверху страницы карточка «Итог» со статусом, цифрами и выводом последнего шага (у параллельной группы в конце — всех её участников), а CLI печатает тот же вывод после строки «Итог:». Проваливаться в итерации нужно только за подробностями. Журнал запуска лежит в `runs/<дата>-<flow>/`:

```
runs/2026-10-06_11-40-57-example-blocks/
├── flow.yaml                 flow в том виде, в каком он запускался
├── run.json                  статус, стоимость, sessionId и токены каждого этапа, итог (final)
├── attachments/              вложения к задаче (если были)
├── artifacts/                артефакты запуска (у flow с artifacts): plan.md, decisions.md, …
├── artifacts-history/        версии артефактов после каждого изменения: ideas/0001.md, 0002.md, …
└── 01-slogan/iter-01/        (у flow из одного блока — сразу iter-01/)
    ├── 01-write.prompt.md       что ушло агенту
    ├── 01-write.transcript.md   что он делал: текст и вызовы инструментов
    ├── 01-write.output.md       итоговый вывод этапа
    └── condition.json           результат условия
```

Любую сессию можно открыть в обычном Claude Code: `claude --resume <sessionId>` (запускать из директории проекта).

Артефакты остаются в папке запуска и после его конца: на странице запуска их видно в панели «Артефакты» со всеми версиями, у завершённого запуска — только для чтения. Если по ходу появились предупреждения, в папке может быть и `artifacts-quarantine/` — туда раннер убирает посторонние файлы из папки артефактов.

## Командная строка

То же самое без UI. В dev-режиме команды идут через `npm run agentgraph --`:

```bash
# сгенерировать flow и сразу запустить
npm run agentgraph -- "Почини падающие тесты, тесты не менять" --cwd ~/code/my-repo

# разовый запуск: сгенерировать и запустить, flow не сохранять
npm run agentgraph -- "Переименуй utils в shared и поправь импорты" --cwd ~/code/my-repo --once

# только сгенерировать, посмотреть план
npm run agentgraph -- gen "Добавь эндпоинт /health с тестами" --cwd ~/code/my-repo
npm run agentgraph -- show add-health-endpoint

# поправить flow словами
npm run agentgraph -- edit add-health-endpoint "добавь этап ревью"

# запустить готовый flow, с ходом сессий в консоли
npm run agentgraph -- run add-health-endpoint --cwd ~/code/my-repo --max-budget 3 -v

# продолжить фичу по тегу: блок тега — в задачу, после done — обновить саммари; список тегов
npm run agentgraph -- run add-health-endpoint --cwd ~/code/my-repo --tag health --input "Поправь замечания ревью"
npm run agentgraph -- tags
```

Опции: `--cwd`, `--input` (подменить задачу), `--once` (разовый запуск, только с формой «сгенерировать и запустить», без `-o`), `--max-iterations`, `--max-budget` (USD на весь запуск), `--model`, `--tag <slug>` (тег любого вида, можно несколько раз; новый заводится тегом задачи), `--no-save-tag` (с `--tag`: саммари тегов задачи после запуска не обновлять), `--auto-tag` (без тега задачи: новый тег заведёт ИИ по тексту задачи), `-v`. `agentgraph tags` показывает вид каждого тега. Полный список: `npm run agentgraph -- --help`.

Чтобы вызывать просто `agentgraph` из любой папки:

```bash
npm run build && npm link
```

Без `npm run build` команда `agentgraph` не заработает: она запускает собранный `dist/`, а в архиве его нет.

В конце CLI печатает строку «Итог:» (статус, итерации, стоимость), а под ней вывод последнего этапа; длинный вывод обрезается до 4000 знаков с путём к полному файлу.

У flow с артефактами CLI после итога печатает строку «Артефакты:» с путём к их папке, а `show` перечисляет артефакты flow.

Разница с UI: в CLI нет паузы (запуск с `pause_marker` завершится ошибкой с текстом вопросов) и правки артефактов на ходу (шаги идут подряд), а вопросы агента задаются в терминале.

## Запуск из чата Claude Code: скилл `/agentgraph`

В `.claude/skills/agentgraph/` лежит скилл: в чате Claude Code говоришь «запусти flow X на этом проекте», он поднимает UI-сервер (если тот не запущен), стартует flow, пересылает вопросы агента тебе в чат и в конце пересказывает итог. У flow с артефактами скилл показывает их, по твоей просьбе правит артефакт, а ответ на паузу записывает в артефакт решений, как поле «Ответ» в UI.

**Разовый запуск из чата.** Если сохранённого flow под задачу нет, скилл делает разовый: `agentgraph.mjs draft --task-file F --cwd DIR` генерирует flow, ничего не сохраняя, и возвращает план (этапы с инструментами, условие) и путь к YAML черновика. Скилл показывает план и спрашивает согласие: инструменты flow разрешаются без подтверждения. Только после «Запустить» идёт `agentgraph.mjs start --spec-file <yaml> --cwd DIR`. Сохранить flow такого запуска потом — `agentgraph.mjs save-flow <id> [--name N] [--folder D]`.

Внутри папки agentgraph скилл доступен сразу. Чтобы он работал из любого проекта, подключи его глобально:

```bash
mkdir -p ~/.claude/skills
ln -s "$(pwd)/.claude/skills/agentgraph" ~/.claude/skills/agentgraph
```

Команду выполняй из корня agentgraph. Корень проекта скилл находит сам по симлинку; если запускаешь его иначе, задай переменную `AGENTGRAPH_HOME`.

## Flow из сессии: скилл `/session-to-flow`

Решил задачу в обычной сессии Claude Code, наткнулся по дороге на ошибки и тупики и хочешь, чтобы в следующий раз это делал flow? В конце той же сессии скажи «сделай flow из этой сессии» или вызови `/session-to-flow`. Прошлую сессию можно передать по id.

Скилл читает транскрипт сессии (`~/.claude/projects/<проект>/<id>.jsonl`). Хелпер `digest.mjs` сжимает его в дайджест: реплики пользователя, ошибки, отказы, повторы, отчёты сабагентов; секреты маскирует. По дайджесту скилл раскладывает итоговый рабочий путь по этапам, а проверенные команды и подводные камни по промптам этапов. Проверки уходят в условие остановки, а действия с последствиями (push, MR) — в отдельный блок с явным согласием. Затем скилл проверяет flow через `agentgraph show` и сохраняет его в `flows/<папка>/`. Подключается глобально так же, как `/agentgraph`:

```bash
ln -s "$(pwd)/.claude/skills/session-to-flow" ~/.claude/skills/session-to-flow
```

## Сколько это стоит и как не переплатить

- Каждый этап — отдельная сессия Claude Code (~33K токенов системного промпта; повторные сессии в течение часа читают его из кэша дёшево). Flow из 3 этапов на 3 итерации = 9 сессий плюс проверки условий.
- Стоимость на странице запуска — оценка по прайсу API. При входе по подписке расход считается по условиям подписки.
- Ограничители: **лимит стоимости** в форме запуска (`--max-budget`), `max_iterations` у цикла, `max_turns` и `max_budget_usd` у этапа или в `defaults`.
- Инструменты из `tools` этапа разрешаются **без подтверждения**. Давай `Bash`, `Edit` и `Write` только тем этапам, которым они действительно нужны, и смотри на них перед запуском чужого или сгенерированного flow.

## Развёртывание и общий доступ

agentgraph — **локальный инструмент**: у каждого своя копия на своей машине.

- Сервер слушает только `127.0.0.1`, авторизации нет. Не выставляй его в сеть: любой, кто до него достучится, сможет запускать агентов с правами на файлы и shell. От чужих страниц в твоём же браузере сервер защищён: он отвечает только на адреса 127.0.0.1, localhost и [::1] (любой порт, так что SSH-туннель работает), а запросы, меняющие состояние, принимает только со своей страницы или без заголовка `Origin` (curl, скилл).
- Чтобы пользоваться им на удалённой машине (например, на мощном сервере рядом с репозиторием), подними там `npm run ui` и пробрось порт по SSH:
  ```bash
  ssh -L 4747:127.0.0.1:4747 user@host
  ```
  Потом открой http://127.0.0.1:4747 у себя.
- Flow пересылай файлами: положи `.yaml` в `flows/` (или в подпапку), и после обновления страницы он появится в UI.
- Поделиться самим инструментом: `npm run share` собирает чистый архив `release/agentgraph-<версия>-<дата>.zip` (подробности ниже).

### Переменные окружения

| Переменная | Зачем |
|---|---|
| `AGENTGRAPH_HOME` | где лежат `flows/` и `runs/`; по умолчанию корень проекта (сборка UI `dist/web` всегда рядом с кодом) |
| `AGENTGRAPH_URL` | адрес сервера для скилла `/agentgraph`; по умолчанию `http://127.0.0.1:4747` |
| `AGENTGRAPH_NOTIFY` | `off` — без системных уведомлений, `log` — писать их в лог сервера |
| `AGENTGRAPH_CONFIG_DIR` | настройки Jira, проектов и worktree, токен Jira; по умолчанию `~/.agentgraph` |
| `ANTHROPIC_API_KEY` | авторизация по API-ключу вместо входа по подписке |
| `AGENTGRAPH_CLAUDE_EXECUTABLE` | путь к CLI Claude Code для Agent SDK; по умолчанию SDK находит его сам, десктопное приложение задаёт его на `app.asar.unpacked` |

## Как поделиться проектом с командой

```bash
npm run share                       # → release/agentgraph-0.1.0-2026-10-06.zip
npm run share -- --out ~/Desktop    # положить архив в другую папку
npm run share -- --no-examples      # без flows/example/
```

В архив попадают исходники (`src/`, `web/`, `bin/`, `scripts/`), `package.json` и `package-lock.json`, документация, скиллы `/agentgraph` и `/session-to-flow` и примеры из `flows/example/`. Не попадают твои flow (всё остальное в `flows/`), запуски (`runs/`), `node_modules`, `dist` (сборку UI `npm run ui` у получателя сделает сам), `.git` и локальные настройки `.claude/`. Список файлов берётся из git с учётом `.gitignore`, поэтому незакоммиченные файлы тоже попадут, если они не в игноре.

Получатель распаковывает архив и идёт по разделам «Установка» и «Запуск» выше.

Если у проекта есть git remote, туда уходит только этот же общий набор, личная история с твоими flow не публикуется. `npm run share -- --push` собирает набор из закоммиченного `main` (не из рабочего дерева) и кладёт его одним коммитом поверх `main` в `origin`. Если набор не изменился, публиковать нечего. `--ref` и `--remote` задают другую ветку и другой remote.

MR коллег вливаются прямо в `main` в `origin`, мимо твоего локального `main`. Поэтому `--push` сначала проверяет, что изменения, влитые в `origin` после последнего снимка, уже есть в твоём `main`, иначе снимок их откатил бы. Если нет, публикация отказывает и перечисляет коммиты: перенеси их в `main` (`git fetch origin && git cherry-pick -x <sha>`) и повтори. `--overwrite-remote` затирает их осознанно.

Чтобы обычный `git push` не отправил личное по ошибке, поставь хук. Он отклоняет push, если в каком-нибудь новом коммите есть файлы вне общего набора:

```bash
printf '#!/bin/sh\nexec bash "$(git rev-parse --show-toplevel)/scripts/share.sh" --pre-push "$1"\n' > .git/hooks/pre-push
chmod +x .git/hooks/pre-push
```

## Релизы и CI

Версия — в `package.json`, по semver. После крупного обновления подними её и опубликуй:

```bash
npm run release -- minor --dry-run   # показать раздел changelog, ничего не меняя
npm run release -- minor             # major | minor | patch
npm run share -- --push              # снимок и тег v<версия> в origin
```

`npm run release` берёт заголовки коммитов `feat:` и `fix:` с прошлого релиза (коммит `chore(release): vX.Y.Z`), пишет из них раздел в `CHANGELOG.md`, поднимает версию в `package.json` и `package-lock.json` и коммитит это одним коммитом. Другие типы коммитов в changelog не идут. В первый раз прошлого релиза нет, укажи начало: `--from <коммит>`. `CHANGELOG.md` уходит в публичный `origin`, поэтому перед публикацией прочитай пункты: в заголовках коммитов бывают имена личных flow. Поправить пункты можно `git commit --amend`.

`npm run share -- --push` замечает, что версия новее, чем в `origin`, и в том же push ставит на коммит публикации тег `v<версия>`. Тег с такой версией уже есть — отказ: подними версию.

CI в GitLab (`.gitlab-ci.yml`):

- на каждый MR и на `main` — `npm ci`, `npm run typecheck`, `npm test` и сборка UI `npm run build:web` на Node 24;
- на тег `vX.Y.Z` — релиз в GitLab (Deploy → Releases) с разделом этой версии из `CHANGELOG.md`.

Чтобы MR нельзя было влить с красными тестами, включи в настройках проекта Settings → Merge requests → «Pipelines must succeed».

Разработка: `npm run ui` запускает сервер через `tsx` прямо из `src/`, сборка сервера не нужна; после правок `src/` перезапусти его. UI с горячей перезагрузкой — `npm run dev:web` при запущенном `npm run ui`: Vite на http://127.0.0.1:5173 проксирует `/api` и SSE на сервер (другой адрес сервера — `AGENTGRAPH_API=http://127.0.0.1:4848 npm run dev:web`). Без dev-режима после правок `web/` перезапусти `npm run ui`, он пересоберёт UI сам. Перед коммитом: `npm run typecheck && npm test && npm run build:web`. Правила UI (стек, где что лежит, как проверять) — `.claude/agents/ui-engineer.md`; история переноса со старого `ui/` — `docs/redesign/react-migration.md` (комментарии вида «порт `ui/app.js` …» ссылаются на старый UI, он есть в git до коммита этапа 7).

После обновления Agent SDK прогони `npx tsx scripts/check-sdk-hooks.mts` (тратит до $5, по умолчанию на haiku; `--only <сценарии>` и `--budget` сужают проверку): защита артефактов опирается на хук перед вызовом инструмента, и новая версия SDK может перестать вызывать его, например в сабагентах. Отчёт ляжет в папку, которую скрипт напечатает в конце; любая строка `FAIL` — повод не обновляться, пока не разберёшься.

## Если что-то не так

| Симптом | Что делать |
|---|---|
| Этап сразу падает с ошибкой авторизации | проверь, что `claude` в терминале работает (`/login`), или задай `ANTHROPIC_API_KEY` |
| `EADDRINUSE` при `npm run ui` | порт занят: уже запущен другой сервер, или укажи `--port` |
| `agentgraph: command not found` или ошибка про `dist/cli.js` | `npm run build && npm link`, либо используй `npm run agentgraph -- …` |
| Агент «не может» редактировать файлы или запускать команды | нужного инструмента нет в `tools` этапа: в headless-режиме всё, что не разрешено, автоматически отклоняется |
| Агент не видит правил проекта | открой «Контекст», выбери директорию проекта (и этап) и проверь, попал ли CLAUDE.md в список |
| Запуск висит со статусом «ждёт ответа» | агент задал вопрос: ответь на главной или на странице запуска |
| Запуск упал со статусом `failed` и ошибкой этапа (например, «computer went to sleep») | сессия этапа кончилась ошибкой; устрани причину и нажми «Продолжить с места остановки» |
| Запуск «оборвался» | сервер перезапускали во время работы; на странице запуска нажми «Продолжить с места остановки» |
| Не видно системных уведомлений (macOS) | разреши уведомления для Script Editor или terminal-notifier в «Системные настройки → Уведомления» |
| Jira отвечает 401 | неверный email или токен; нужен API-токен с id.atlassian.com, пароль от Jira не подходит |
| MR не грузятся | `glab` не установлен или не авторизован на хосте проекта: `glab auth login --hostname <хост>` |
| Секция «Мои MR: нужно внимание» пустая или с ошибкой проекта | `glab` не авторизован на хосте проекта: `glab auth login --hostname <хост>`, потом ↻ в секции |
| «Ветка уже выгружена в основном checkout» | git не даёт выгрузить одну ветку дважды: переключи основной checkout на другую ветку или работай в нём без worktree |
| Flow не появился в списке | проверь, что файл лежит в `flows/` (или подпапке на один уровень) и `name` в нём уникален; обнови страницу |
| Артефакт не правится: «пишет этап X» | этот артефакт сейчас пишет идущий шаг; нажми «Пауза» и поправь, когда шаг доработает |
| «Сохранить» отклонено: файл изменён после того, как ты его открыл | артефакт поменял этап или другая вкладка; «Перечитать» возьмёт версию с диска, «Сохранить поверх» запишет твой текст |
| Этап с артефактами падает с «Reached maximum number of turns» | даже с `tools: []` модель часто сначала открывает артефакт инструментом; убери у такого этапа `max_turns` 1–3 или подними до 5 и больше |
